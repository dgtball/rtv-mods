# Управление количеством в клетке снаряжения: патроны и обоймы

Дата: 2026-10-14
Целевая версия: 4.17.1 (новая функциональность UI; 4.17.0 уже выпущен)

## Проблема

Клетка снаряжения (шаг 2 «Снаряжение») управляет количеством двумя микро-кнопками `−`/`+`
и строкой счётчика, собранной наспех:

- **Патроны.** `_bump_gear` шагает на **1** (`VTKUI.gd:2535` → `VTKDraft.set_gear_amount`,
  `VTKDraft.gd:222`). До полного стака (`maxAmount = 300`) — до 300 тапов. В данных игры у патронов
  есть `defaultAmount` (стак, которым патроны выпадают): 12x70 = 10, 7.62x54R / 9x39 = 20,
  5.45 / 5.56 / 7.62x39 = 30, .45 / 9x18 / 9x19 = 50. Полный стак — `maxAmount = 300`. Отдельной
  кнопки «набрать полный стак» нет.
- **Обоймы.** У обоймы в сете `count` — число обойм, `full_mag` — заполнены ли они (тумблер
  `Full magazine` в `VTKUI.gd:1277`). Кнопка-тумблер зажата в строке A рядом со счётчиком
  (`VTKUI.gd:2688`): шрифт 8, поля 2/2, состояния «вкл/выкл» визуально почти не различимы.
- Счётчик рисуется **дважды**: `×N` в строке A (`VTKUI.gd:2679`) и голое `N` в строке B
  (`VTKUI.gd:2703`). Точное значение (например, 45 патронов) задать нельзя — только шагами.

## Цели

1. `+/−` у патронов меняют количество на **стак** калибра (`defaultAmount`), пол = 1
   (удаление только через `✕`), потолок = `maxAmount`.
2. Кнопка **Full** у патронов: разово выставляет `amount = maxAmount`. Горит, когда уже полный.
3. Кнопка **Full magazine** у обойм переезжает вниз под `+/−` и становится крупной.
4. Визуальная метка вкл/выкл для обеих кнопок Full: заливка + золотая точка (`●`) слева; выкл —
   серый контур без точки.
5. Клик по числу открывает ввод точного значения (Enter — применить, Esc — отменить),
   для всех клеток снаряжения.
6. Клик по патронам в каталоге (шаг 2 «Снаряжение») добавляет **одну коробку** — стак калибра
   (`defaultAmount`), а не 1; повторный клик добавляет ещё коробку. Потолок — `maxAmount`.
   Так клик и шаг `+/−` живут в одном масштабе.

## Не-цели

- Не трогаем логику шага 1: целевой слот, `add_to_slot`, вытеснение, авто-экип. Меняется только
  количество, которым патроны попадают в снаряжение.
- Не меняем добавление остальных предметов: не-патроны по-прежнему +1 на повторный клик
  (правило бережёт стакаемые от прыжка на `maxAmount`), обоймы — +1 обойма.
- Не вводим тумблер Full↔Empty у патронов («пустых патронов» не бывает).
- Не рефакторим обвесы и панель обвесов.

## Дизайн

### Раскладка клетки (шаг 2, `gi >= 0`) — единая форма

```
иконка
имя (2 строки)
[ − ]  ⟨число⟩  [ + ]      ← строка A: шаг; число кликабельно → ввод
[    контекстная кнопка   ] ← строка B (только если у предмета есть действие)
                        ✕
```

Строка B по типу предмета:

| Тип | Строка B |
|---|---|
| Патроны (`type == "Ammo"`) | `Full · 300` — разовое действие + индикатор |
| Обоймы (`Attachment` / подтип `Magazine`) | `Full magazine` (вкл) / `Empty` (выкл) — тумблер |
| Снаряжение с обвесами (`_att_panel_needed`) | `rnd. N` — существующая `_make_att_btn`, переезжает из строки A в B |
| Остальное | строки B нет |

Дублирующий счётчик `×N` из строки A убирается: число живёт в степпере строки A. Обоймы и патроны
теперь отличаются содержимым строки B, а не местом счётчика.

### Шаг и клампы

- Патроны: шаг = `defaultAmount` (из ресурса), потолок = `maxAmount` (300), пол = 1.
- Обоймы: шаг = 1 (число обойм), пол = 1, потолок = 99.
- Прочее: шаг = 1 (как сейчас), потолок = `maxAmount`, если он > 0, иначе без потолка; пол = 1.

Пол = 1 означает: `−` никогда не удаляет запись. Удаление — только крестик `✕`.

### Ввод числа (идея №2)

Счётчик в строке A — `Label`. Клик превращает его в `LineEdit` (числовой), Enter/потеря фокуса
применяют значение через `set_gear_amount`, Esc отменяет. Значение клампится теми же полом/потолком,
что и шаг. Обоймы (`count`) тоже редактируются.

### Визуал вкл/выкл

`style_button(b, accent, ...)` при `accent = true` даёт залитую поверхность. Слева от текста —
точка `●` (`Panel` 7×7 со `StyleBoxFlat`, радиус = половина), золотая и со свечением когда включено;
при выключенном — точки нет, `accent = false`, цвет текста `GREY_DIM`.

Состояние:
- Патроны: «включено» = `amount >= maxAmount`.
- Обоймы: «включено» = `Draft.is_full(desc)`.

### `VTKDraft.gd` — чистая `bump_amount`

Инкремент вынести в чистую функцию, чтобы пол/потолок тестировались headless:

```gdscript
func bump_amount(path: String, dir: float, step: float, cap: float) -> void
```

- `t = amount_of(path) + dir * step`;
- `t < 1.0` → `t = 1.0`;
- `cap > 0.0` и `t > cap` → `t = cap`;
- `set_gear_amount(path, t)`.

`_bump_gear` (`VTKUI.gd:2535`) перестаёт принимать сырой `delta`: принимает направление, сам считает
`step`/`cap` из ресурса и зовёт `Draft.bump_amount`.

### `VTKDraft.gd` — шаг при добавлении кликом

`_gear_add` (`VTKDraft.gd:59`) при повторе сейчас жёстко делает `+1` (`:65`), игнорируя `amt`.
Добавить необязательные `step := 0.0` и `cap := 0.0`: при `step > 0` повторный клик прибавляет
`step` (с клампом по `cap`), иначе — `+1`, как раньше:

```gdscript
func _gear_add(path, item_name, amt, type_name, counted, step := 0.0, cap := 0.0) -> void:
	# ...
	if idx >= 0:
		if gear[idx].has("count"):
			gear[idx]["count"] = int(gear[idx].get("count", 1)) + 1
		else:
			var inc := 1.0 if step <= 0.0 else step
			var t := float(gear[idx].get("amount", 1.0)) + inc
			if cap > 0.0 and t > cap:
				t = cap
			gear[idx]["amount"] = t
		return
```

`add` (`:47`) и `add_gear` (`:77`) пробрасывают `step`/`cap` дальше в `_gear_add`. Так правило «+1»
для не-патронов сохраняется (тест «ровно +1 независимо от переданного amount»), а патроны получают
коробку и на повторном клике.

### `VTKUI.gd` — точки правки

- `_info_of` (`:2378`): добавить в словарь `defaultAmount` (рядом с `maxAmount`) для шага патронов.
- `_place_into` (`:2769`): для `type == "Ammo"` первичное `amt` = `defaultAmount` (коробка), плюс
  `step` = тот же стак и `cap` = `maxAmount`; прочие стакаемые — `maxAmount` (как сейчас), оружие — 1.
  `step`/`cap` пробрасываются в `add` / `add_gear`. Если `defaultAmount` нет — как раньше (1).
- Новые хелперы: `_gear_step(path) -> float`, `_gear_cap(path) -> float` (патроны → `maxAmount`,
  обоймы → 99, иначе `maxAmount` или 0).
- `_make_full_ammo_btn(path, desc) -> Button`: текст `Loc.txt("Full") + " · " + str(cap)`; `pressed`
  → `set_gear_amount(path, cap)` + `refresh`. Метка/заливка по `amount >= cap`.
- `_make_full_mag_btn` (`:1277`): общая пометка заливка+точка, крупная строка B (не compact).
- `_make_item_cell` (`:2631`): строка A — степпер (`−`, число, `+`); строка B — контекстная кнопка
  из таблицы выше; `rnd.` переезжает в строку B; `custom_minimum_size.y` клетки снаряжения
  176 → ≈200 (добавился ряд).
- Клик по числу: `Label` → `LineEdit` на месте (см. «Ввод числа»).

### Локализация

Новый ключ `Loc.txt("Full")` (EN `Full`, RU `Полный`). `Full · 300` собирается из ключа и числа,
составной строки не заводим. Добавить запись в `RU` (`VTKLoc.gd`) тем же проходом; `keycheck.py`
ловит рассинхрон.
