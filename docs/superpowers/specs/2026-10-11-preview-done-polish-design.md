# Превью, Done и рейл: полировка + фикс поиска — дизайн

Статус: **предложено, ждёт ревью пользователя**.

Версия релиза: **4.13.4** (решение пользователя).

## Проблема

1. **Поиск в шаге 2 «Снаряжение» не работает.** `_entry()`
   (`VTKUI.gd:2197`) возвращает записи каталога `{item, cat, sub}` **без
   ключа `name`**, а `Picker.facets_of` (`VTKPicker.gd:542`) фильтрует
   именно по `e.get("name")` (`:548`). Поле всегда пустое, поэтому при
   непустом запросе не проходит ни один предмет — фасеты и сетка гаснут.
   Контракт зафиксирован в комментарии `facets_of` («нужен `name` для
   поиска»), но `_entry` его не выполняет — регрессия. Шаг 1 ищет по имени
   ресурса напрямую (`_items_for_target`, `:2211`) и работает.
2. **Кнопка хоткея в столбце управления превью ниже остальных.** У `qk_btn`
   стоит `font_size 9` (`VTKUI.gd:658`), у «Применить/Изменить/Удалить» —
   размер темы. Ширину кнопки берут от колонки, а высота у мелкого шрифта
   меньше — кнопка визуально «тоньше».
3. **Экипировка превью ниже инвентаря на ~125px.** Сетка 6×8 с клеткой 55
   (`EQ_CELL`, `EQ_GAP 4`) даёт 350×468, стена инвентаря 8×8 с клеткой 70
   (`INVEN_CELL`, `INVEN_GAP 3`) — 581×581. Нижние края не вровень.
4. **Строки категорий шага «Снаряжение» низковаты** (`_make_facet_row`,
   высота 26/23).
5. **Рейл минималистичен**: имя 11px, плашка «V» 26×26 со скруглением 4,
   нет полосы-разделителя между «Vostok Toolkit» и вкладками.
6. **Шапка карточки превью без разделителя** (в макете `border-bottom`).
7. **Подпись «Раскладка · N предметов» дублирует список сохранённых сетов** —
   нужна убрать из превью и с Done.
8. **Done**: строка `Название: […] Клавиша: […]` живёт отдельно над
   карточкой; нужно перенести поле имени и кнопку хоткея в столбец
   управления.

## Решение

Подход **A1** (единые метрики сеток) и **B1** (один релиз) одобрены
пользователем. Заголовок столбца «УПРАВЛЕНИЕ» на Done остаётся.

### 1. Поиск (шаг 2)

В `_entry()` (`VTKUI.gd:2197`) добавить имя:

```gdscript
func _entry(it) -> Dictionary:
	return {
		"item": it,
		"name": str(it.get("name", "")),
		"cat": Picker.category_of(it.get("slots"), it.get("type")),
		"sub": Picker.subcategory_of(str(it.resource_path), it.get("type")),
	}
```

`_items_for_gear` (`:1500`) уже отдаёт `_entry(it)`, а `_refresh_gear_catalog`
(`:1296`) гоняет результат через `facets_of` — после правки фильтр получает
имя и поиск оживает. Шаг 1 не трогаем: `_items_for_target` фильтрует по имени
ресурса, а `_target_filter_items` (`:2104`) сам собирает `name` из ресурса.

### 2. Кнопки управления превью — одинакового размера

Убрать `qk_btn.add_theme_font_size_override("font_size", 9)` (`:658`): кнопка
получает размер шрифта темы, как соседние, и совпадает с ними по высоте (и
ширине — `size_flags_horizontal = SIZE_EXPAND_FILL` уже выставляется всем в
`_make_control_column`, `:585`).

### 3. Экипировка вровень с инвентарём (A1)

Единые метрики для обеих сеток: клетка 70, зазор 3.

- `EQ_CELL` 55 → **70**, `EQ_GAP` 4 → **3** (`VTKUI.gd:1066-1067`). Формула
  сетки не меняется, ячейки остаются квадратными.
- `_make_equip_preview` (`:1750`): обернуть `_make_equip_grid` в
  `MarginContainer` с отступом 6 со всех сторон — ровно как у инвентаря
  (`_make_inventory_panel:1882-1890`). Тогда высоты панелей совпадают точно:
  `head + 6 + (6 + 581 + 6)` у обеих.
- `EQ_COL_W` 375 → **447** (`:1065`): 6·70 + 5·3 = 435 плюс поля панели 12.

Побочный эффект (осознанный, единые константы): сетка **шага 1 «Экипировка»**
тоже становится 435×581, его левая колонка — 447. Превью повторяет укладку
редактора, размеры держим общими.

### 4. Категории шага «Снаряжение» — выше на 5px

`_make_facet_row` (`:1373`): `row.custom_minimum_size` 26 → **31** для
категорий (`level = false`) и 23 → **28** для подкатегорий (`level = true`) —
оба уровня растут на 5px, иерархия отступа сохраняется. Ширину **не** трогаем
(пользователь уточнил: ширина нормальная).

### 5. Рейл

`_build_ui` (`:440-484`):

- Имя «VOSTOK TOOLKIT»: `font_size` 11 → **14**.
- Плашка «V»: `custom_minimum_size` 26×26 → **30×30**, `corner_radius_all`
  4 → **8**, буква «V» 13 → **15**.
- Версия: `font_size` 9 → **10** (комментарий — «шрифт побольше»).
- Полоса-разделитель: `ColorRect` высотой 1px, цвет `#2a2419`, на всю ширину
  панели, между рейлом (низ 54) и вкладками (верх 58) — на y≈56.

### 6. Разделитель под шапкой карточки превью

`_refresh_preview` (`:633-647`): после `card_head` добавить `ColorRect`
высотой 1px с `size_flags_horizontal = SIZE_EXPAND_FILL` и цветом `#2a2419` —
линия на всю ширину карточки, как `border-bottom` в макете.

### 7. Убрать подпись «Раскладка · N предметов»

- Превью: удалить `cap` (`VTKUI.gd:641-646`) и добавление в `card_head`
  (`:646`). Остаётся только имя.
- Done: удалить `_done_meta` — объявление (`:101`), создание и добавление
  (`:1553-1557`), обновление текста (`:1585-1587`).

### 8. Done: имя и хоткей в столбце управления

`_build_page_done` (`:1508`):

- Убрать строку `name_row` целиком (метка «Название:», `_name_input`, метка
  «Клавиша:», `_bind_btn`) и `_done_meta`.
- Поле имени и кнопку хоткея перенести в колонку управления.

`_refresh_page_done` (`:1566`) собирает столбец управления как
`[поле имени, кнопка хоткея, Сохранить, Отмена]` под тем же заголовком
«УПРАВЛЕНИЕ» (`_make_control_column`).

Так как `_done_preview` пересобирается (дети удаляются и `queue_free`),
`_name_input` и `_bind_btn` создаются один раз в `_build_page_done` и
**перевешиваются** в новую колонку при каждом обновлении: перед очисткой
`remove_child(_name_input)` / `remove_child(_bind_btn)`, после сборки —
`add_child`. Иначе узлы ушли бы вместе со старым столбцом, потеряв текст и
фокус. `_bind_btn`/`_done_bind_btn` продолжают указывать на кнопку хоткея —
логика биндинга (`:285-343`) не меняется.

## Локализация

Правило «английский — исходный язык» сохраняется. После правок становятся
stale (единственные потребители — удаляемые `cap`/`_done_meta`) и удаляются из
`VTKLoc.gd`:

- `'Name:'` (`:68`) — метка убрана.
- `'Hotkey:'` (`:52`) — метка убрана.
- `'Loadout'` — использовался только в подписи `cap`/`_done_meta`.
- `' items'` — использовался только в подписи `cap`/`_done_meta`.

Остаются: `'Enter a name...'` (placeholder поля), `'Controls'` (заголовок
столбца), `'Name already taken!'` (валидация). Новых ключей нет.

## Стенды

`.check/layout_check.py`:

- `FUNCS` `("_build_page_done", ["_build_set_preview({}, [], false,", "_done_meta"], …)`
  (`:307-310`): `_done_meta` удаляется — заменить маркер на новую привязку
  (например, `_name_input`), иначе стенд завалится на отсутствующем символе.
- `PRESENT`: убедиться, что нет ссылок на удалённые `cap`/`_done_meta`.
- `GONE`: дату подписи можно оставить; новых GONE не требуется.

## Проверка

- `py .check\layout_check.py` — GONE/PRESENT/FUNCS зелёные.
- `powershell -NoProfile -ExecutionPolicy Bypass -File .check\check.ps1` —
  парсинг всех `.gd` + headless-тесты (`tests passed`, код 0, без
  `SCRIPT ERROR`/`Parse Error`/`Invalid call`).
- `python .check\keycheck.py` — `Name:`/`Hotkey:`/`Loadout`/` items` удалены,
  новых stale-ключей нет.
- `python .check\encoding_check.py` — кодировка чистая (кириллица не
  задвоена).
- **Регресс-тест поиска**: в `test_picker.gd` добавить проверку `facets_of` —
  на записях с `name` запрос находит предмет, без `name` (как было) фильтр
  гасит всё. Покрывает контракт, который нарушал `_entry`.
- Ручная проверка в игре:
  - шаг 2: ввод `ak` в поиск находит АКМ; `en` — тоже; пустой запрос — всё;
  - превью: четыре кнопки управления одного размера; низ экипировки вровень
    с инвентарём; под шапкой и карточкой — линии; подписи «Раскладка · N
    предметов» нет;
  - шаг 2: строки категорий чуть выше;
  - рейл: крупнее имя и плашка, полоса между рейлом и вкладками;
  - Done: поле имени и кнопка хоткея в столбце управления, меток
    «Название:/Клавиша:» нет; сохранение и биндинг работают; текст и фокус
    поля имени не теряются при пересборке.
