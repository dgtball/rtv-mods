# Превью сета: силуэт + стена инвентаря (4.9.1)

Дата: 2026-10-09.
Статус: принято (brainstorming с пользователем, макет `.docs/sets-mockups/s1-square-icons.html`).

## Цель

Переделать превью сета из текстовой сводки (`_fill_summary`) в визуальную
двухпанельную картинку в духе S1:

- **левая панель** — «Экипировка · <имя сета>»: силуэт с сеткой слотов (оружие,
  зона тела, мелкие слоты), как на вкладке экипировки;
- **правая панель** — «Инвентарь»: стена 8 колонок с предметами `gear` сета,
  размер ячейки — реальный `size` предмета, иконка + бейдж количества.

Макет пользователя: `.docs/sets-mockups/s1-square-icons.html`. Именование приходит
из предшествующего макета сетки: силуэт и клетки уже реализованы (4.9.0) на
вкладке «Экипировка».

## Где показывается

Одно и то же превью в двух местах, у них общий код рисования, но разные источники:

1. **Правая колонка вкладки «Сеты»** (`_refresh_preview`): выбранный сет, черновика нет.
   Источник — `pack` из `VTKData.get_set`. Футер: Применить / Изменить / хоткей / ✕.
2. **Шаг 3 «Готово» редактора** (`_refresh_page_done`): редактируемый черновик.
   Источник — `_draft`. Футер: Сохранить сет / Отмена (имя и хоткей остаются выше).

## Расположение внутри панели

```
Левая панель «ЭКИПИРОВКА · <имя сета>»   | Правая панель «ИНВЕНТАРЬ»
-----------------------------------------|------------------------------
[S1 клетки, read-only]:                  | <шапка: ИНВЕНТАРЬ · N предметов · сетка 8 колонок>
  оружие: 2 широкие клетки               | [стена 8 колонок, пролёты по size]
  тело: сетка 2×4 поверх силуэта         | -------------------------------------
  мелкие: сетка 2×5                      | [футер действий (в правой колонке «Сеты»)]
-----------------------------------------|------------------------------
```

Панели в HBoxContainer с общим зазором. На «Сеты»-колонке футер действий живёт
под стеной (как в макете); на «Готово» под суммой — кнопки Сохранить/Отмена.
Поиск по предметам из макета исключён (по решению пользователя): стена показывает
весь состав `gear` сета, фильтровать нечего.

## Компоненты

### Read-only клетки (`_make_equip_cell` / `_make_weapon_cell`)

Клетки уже есть, но завязаны на `_draft` и интерактив (клик, ✕, ховер-рамка,
панель обвесов). Для превью нужен read-only режим:

- добавляется параметр `interactive := true`; при `false`:
  - источник `desc` — аргумент, а не `_draft.equip.get(slot)` (вызывающий передаёт
    `desc` из своего словаря/дрёфта; для «Готово» — `_draft.equip`, для превью — `pack.equip`);
  - не вешается `_on_slot_row_input`, `_attach_motion`, кнопка ✕ не ставится;
  - точка занятости и подпись слота сохраняются (занятая клетка — иконка предмета,
    пустая — имя слота серым).
- для пустого слота передаётся пустой dict; `occupied = false`.

Разбиение на зоны — `Picker.equip_layout(Picker.all_slots(lists))`, как на вкладке
экипировки: `weapons`, `body`, `small`. Список слотов считаем так же, как
`_refresh_slots`: из `_db_items` каталога. (`Picker.all_slots` уже чистая и
тестируется headless.)

### Стена инвентаря (`_make_inventory_wall`)

- Контейнер: 8 колонок. Укладка — простой «первый подходящий ряд» (first-fit по
  строкам), не оптимальная упаковка: идём по предметам `gear` в порядке сета,
  каждый занимает `w×h` ячеек из реальных полей предмета (`size` — Vector2 ячеек,
  читаем headless-пробником: 1×1…8×2). Если предмет не влезает в текущую строку —
  переходим на следующую. `w > 8` не бывает (max 8); в крайнем случае режем до 8.
- Ячейка: Panel с `custom_minimum_size = (w*CELL - gap, h*CELL - gap)`, где
  `CELL` ≈ 52px. Иконка — `Picker.item_art(_item_icon(item))`, бейдж количества —
  `Draft.shown_count(desc)` в правом нижнем углу (только если > 1? — нет, показываем
  всегда `xN`, как в игре; для патронов с калибровкой — `xN` от `shown_count`).
  Подпись отсутствует; тултип — имя предмета.
- `size` берётся из ресурса через `_cell_resource`/`_item_info`; если поля нет —
  ячейка 1×1.
- Пол стены: размеры фиксированные (`custom_minimum_size` на панели), без
  вертикального `SIZE_EXPAND_FILL` на контейнере в этом узле — высоту даёт
  ScrollContainer предка (памятка из AGENTS.md: флаг обязан дойти до `_editor_panel`).

Поиск не нужен: решено на макете, фильтрация стены не несёт смысла — это сводка
состава сета.

## Поведение

- Пустой сет (`_draft.item_count() == 0` / пустой `pack`): слева — заглушка
  «Сет пуст», справа — пустая стена.
- Слот в `equip` без предмета в сете: пустая клетка с именем слота (серым) — сетка
  всегда одинаковая, чтобы сверяться с вкладкой экипировки.
- Тултипы у клеток слева — имя предмета (как на вкладке экипировки).
- «Готово»: панель перестраивается в `_refresh_page_done` так же, как сейчас
  перестраивается `_fill_summary` (очистить и наполнить заново).

## Данные

- `pack.equip`: {slot: desc} — источник левой панели (превью).
- `pack.gear`: [desc] — источник стены.
- `Draft.load_from(pack)` уже даёт `d.equip` / `d.gear` для «Готово»; для превью
  копия `pack` как есть.

## Не делаем (Non-goals)

- **Живое состояние персонажа не читаем**: «не показывать надетое» в исходной
  формулировке — это классификация «экипировка → силуэт, снаряжение → стена», а не
  фильтр по текущему инвентарю героя. Дубли (предмет и в силуэте, и в стене) —
  показываем, как в макете.
- Клетки превью не кликабельны: выбор остаётся на шагах 1–2.
- Нет оптимальной упаковки стены и перетаскивания.

## Тестирование

- `.check/check.ps1`: parse всех скриптов + тесты (все зелёные).
- `layout_check.py`: обновить списки `PRESENT` новыми билдерами
  (`_make_inventory_wall`, `_build_set_preview`), если они «обязаны быть».
- `keycheck.py`: новые подписи («Инвентарь» и т.п.) — сверить, что ключи есть в RU.
  Поискового поля нет, имена предметов не локализуются (AGENTS.md).
- Иконки: расширяемых правил нет; визуальная проверка в игре (стена создаёт
  `Picker.item_art` — headless-тесты уже покрывают арт).

## Выходные узлы (архитектура)

- `_make_inventory_wall(items: Array) -> Control` — чистая сборка стены, вход —
  список desc. Размещение и бейджи внутри.
- `_make_equip_preview(pack_or_draft) -> Control` — сборка левой панели
  (оружие + силуэт + мелкие) из уже существующих read-only клеток.
- Обе собираются в `_build_set_preview(items_source) -> Control`, который подставляет
  и превью-колонка, и «Готово».
- `_fill_summary`, `_summary_head`, `_summary_line`, `_equip_row_text` становятся
  мёртвыми после замены последнего вызова — удаляются (правило stale в AGENTS.md).
  `Draft.item_count`, `Picker.equip_layout`, `Picker.all_slots` остаются в использовании.
