# Road To Loot — категории по слотам экипировки (спека)

Дата: 2026-10-28 · Мод: Road To Loot (`RTL`, отдельный самодостаточный) · База: рабочее дерево 0.3.0
Затрагивает `RTLCategory.gd` (полная замена содержимого) и `RTLRoll.gd` (маска статов + снятие
аннотации параметра). Пулы аффиксов (`RTLPool.gd`), применение к игре и UI не трогаем.

## 1. Намерение

Категория предмета (`weapon`/`clothing`/`other`) — единственный вход в выбор пула аффиксов:
`Category.of_item()` вызывается из `RTLBoot.roll_for()` и `RTLBoot.reroll_item()`, а `rollable()`
решает, роллить ли предмет вообще. Сейчас таблица категорий написана по догадке, а не по данным
игры, и расходится с ними в обе стороны: теряет экипировку (поясные сумки, ножи) и цепляет
не-экипировку (пластины брони, ствол KAR-21). Хотим, чтобы категорию задавали **слоты**, которые
игра сама проставляет предмету, — это единственный признак, который не надо угадывать.

## 2. Цели

- Категория выводится из `ItemData.slots`; таблица типов удаляется.
- Поясные сумки (4) и ножи (3) попадают в пул аффиксов: сумка — `clothing`, нож — `weapon`.
- Гранаты (4), карта и спички (3), гитара и губная гармошка (2), удочка (1) в пул не попадают.
- Пластины брони (5) и ствол KAR-21 больше не получают аффиксов.
- Нож не получает `recoil` и `fire_rate`: у него есть только `damage`.

## 3. Не-цели

- **Пластины брони и электроника со слотами** (`Light`/`Time`/`NVG`, 6 предметов) — вторая
  итерация. Пластины остаются в `other` (у них пусто в `slots`), электроника — тоже.
- Vostok Toolkit (`VTK`) не меняется: его picker фильтрует по слотам напрямую, а таблица
  `CATEGORY_ALIASES` покрывает все 22 реальных `type` без утечек (проверено).
- Пулы аффиксов, их диапазоны, веса и `needs` — без изменений.
- Применение аффиксов к статам в игре (`weapon_totals`/`clothing_totals` пока не вызываются
  ниоткуда) — не эта задача.
- Сцена тултипа, палитра редкости, ячейки — без изменений.

## 4. Факты из дампа

Дамп всех ресурсов `res://Items` через `godot --headless --path RTVcopy/extracted`
(`tools/probe/dump_item_types.gd`, `dump_weapon_fields.gd`).

| факт | значение |
|---|---|
| предметов в `res://Items` | 271 (из 628 файлов: 351 — материалы `MT_*` в `Files/`, 6 не грузятся — кассеты с треками) |
| реальных значений `type` | 22 (+ артефакт `" Misc"` с ведущим пробелом) |
| предметов со слотами | 87 |
| `type`, покрывающих экипировку | `Weapon 29`, `Clothing 20`, `Backpack 8`, `Electronics 6`, `Rig 5`, `Armor 5`, `Belt Pouch 4`, `Grenade 4`, `Knife 3`, `Misc 3`, `Helmet 2`, `Instrument 2`, `Fishing 1` |
| `recoil`/`fire_rate`/`low_hp_damage` у всех 32 предметов в оружейных слотах | `null`; непустой только `damage` |
| вложения (`Attachment`, 22) | `slots` пустой у всех, включая магазины, барабан KP-31 и ствол KAR-21 |
| пластины брони (`Armor`, 5) | `slots` пустой, есть только `protection` |
| поясная сумка (`Belt Pouch`) | `capacity = 2.0`, `insulation = 1.0` — по смыслу одежда |
| сколько экипировки видит текущая таблица | 64 из 87 |

Что не так с текущей таблицей:

- из 17 «одежных» типов в игре существуют 4 (`Armor`, `Helmet`, `Rig`, `Backpack`), остальные 13
  (`Gloves`, `Boots`, `Arm`, `Leg`, `Waist`, `Mask`, `Belt`, `Shirt`, `Pants`, `Vest`, `Jacket`,
  `Coat`, `Hood`) — выдуманы;
- самый крупный реальный одежный тип `Clothing` (20 предметов) в списке отсутствует и спасается
  только фолбэком по пути `/clothing/`;
- `Melee` и `Tool` в оружейном списке не существуют;
- фолбэк по пути ловит `Items/Weapons/` целиком, поэтому ствол KAR-21 (вложение без слотов)
  получает пул оружия;
- `Armor` попадает в одежду по `type` (пластины брони получают регенерацию и ёмкость).

## 5. Подход

**A (выбран).** Слоты — единственный источник истины; таблица типов и фолбэк по пути уходят.

Отвергнуто:

- **B. Починить таблицу типов** (добавить `Clothing`, `Belt Pouch`, убрать 13 выдуманных).
  Самый маленький диф, но остаётся ложное срабатывание на стволе KAR-21 и зависимость от папок
  ресурсов, которые ломаются при апдейте игры (это уже случалось в VTK, см. AGENTS.md).
- **C. Слоты плюс проверка по полям предмета.** Невозможно: `recoil`, `fire_rate`,
  `low_hp_damage` пусты у **всех** стволов, фильтр «есть поле — есть аффикс» оставил бы оружию
  один `damage` и обнулил бы пул оружия.

## 6. Правила

```
weapon   = slots ∩ {Primary, Secondary, Knife}, кроме type = Fishing | Instrument
clothing = slots ∩ {Backpack, Rig, Helmet, Head, Torso, Legs, Belt, Feet, Hands}
other    = всё остальное
```

`type` в правиле ножа/оружия нужен ровно один раз: удочка и инструменты формально занимают
`Primary`/`Secondary`, но оружием не являются. Это тот же случай, что `category_allowed` в VTK.

Раскладка 87 предметов экипировки по правилам (проверено симуляцией на дампе):

| категория | состав | штук |
|---|---|---|
| `weapon` | 29 оружия + 3 ножа | 32 |
| `clothing` | 20 одежды + 8 рюкзаков + 5 разгрузок + 2 шлема + 4 поясные сумки | 39 |
| `other` | 6 электроники + 4 гранаты + 3 карта/спички + 2 инструмента + 1 удочка | 16 |

Изменения против текущего поведения: +4 поясные сумки, +3 ножа (в пул), −5 пластин брони,
−22 вложения (из них 21 магазин и так отсекался проверкой `subtype == Magazine`; реально
перестаёт роллиться только ствол KAR-21).

## 7. Маска статов для ножа

Нож — оружие по слоту, но `recoil` и `fire_rate` ему усиливать нечем. Статы `damage` и
`low_hp_damage` остаются: `damage` сливается в ванильную строку `Damage` (у ножей база 20–30),
`low_hp_damage` идёт своей строкой.

Правило живёт в `RTLCategory.stat_allowed(itemData, stat)` — там же, где таксономия, чтобы
`RTLRoll` не знал имён типов. На тире 3 пул ножа — 2 кандидата, поэтому `build_affixes` отдаст
2 аффикса вместо 3: существующий цикл `for i in range(n)` уже выходит по пустому пулу.

## 8. Правки

### `RTLCategory.gd` — переписать целиком

- Удаляется: `WEAPON_TYPES`, `CLOTHING_TYPES`, `of_path()`.
- Добавляется: `WEAPON_SLOTS`, `CLOTHING_SLOTS`, `NON_WEAPON_TYPES` (`Fishing`, `Instrument`),
  `KNIFE_TYPE`, `KNIFE_BLOCKED` (`recoil`, `fire_rate`).
- `of_item(itemData)`: `type` (если исключён — `OTHER`) → слоты оружия → слоты одежды → `OTHER`.
- `stat_allowed(itemData, stat) -> bool`: `false` только для `recoil`/`fire_rate` при
  `type == Knife`; `itemData == null` — `true` (поведение без маски).
- `rollable(itemData)`: `of_item(itemData) != OTHER`. Проверка `subtype == Magazine` и имени на
  `magazine` уходит — магазины и так без слотов.
- Чтение полей — одним `itemData.get(...)` без второго аргумента: он работает и для `Dictionary`,
  и для `Resource` (`Object.get` принимает ровно один аргумент, см. AGENTS.md), а отсутствующее
  свойство даёт `null`, поэтому `str()` берётся только после проверки на `null`.

### `RTLRoll.gd`

- `build_affixes(..., item_data: Dictionary, ...)` → `item_data` без аннотации (см. §9).
- После фильтра `needs` и до фильтра `blocked` — отсев по `Category.stat_allowed`.

### Без правок

`RTLPool.gd` (пулы те же), `RTLBoot.gd` (зовёт `of_item`/`rollable`, сигнатуры не меняются),
`RTLDisplay.gd`, `RTLRows.gd`, `RTLStore.gd`, `RTLSidecar.gd`, `RTLApply.gd`, `RTLStats.gd`.

## 9. Дефект, найденный по дороге (входит в объём)

`RTLRoll.build_affixes()` объявляет третий параметр как `item_data: Dictionary`, а все три вызова
передают `SlotData.itemData` — ресурс `ItemData` (`PROP:itemData type=24 hint=17 hint_string=ItemData`).
Проверено headless на реальном `res://Items/Weapons/AKM/AKM.tres`:

```
SCRIPT ERROR: Invalid type in function 'build_affixes' in base 'GDScript'.
Cannot convert argument 3 from Object to Dictionary.
```

Функция обрывается и возвращает `null`; с `Dictionary` тот же вызов отдаёт три аффикса. Значит
аффиксы через этот путь сейчас не генерируются вовсе, и любая правка категорий осталась бы
ненаблюдаемой. Аннотация снимается в этой же задаче (параметр и так используется только маской
ножа); поведение чинится попутно.

В рабочем дереве на момент спеки фильтры `needs` временно заменены на `ok = true`, а в
`build_affixes`/`roll_for` добавлены отладочные `DBG`-логи (следы диагностики этого дефекта).
Из-за них `test_rtl_roll.gd` красный по трём проверкам, а ещё четыре RTL-теста отстали от
переименования `carry` → `capacity`. План возвращает гейты, снимает логи и приводит тесты к
текущим именам: без зелёного baseline правка категорий не проверяема.

## 10. Что видит игрок

- Ножи и поясные сумки могут выпадать с редкостью и аффиксами.
- Пластины брони и стволы оружия с редкостью больше не выпадают.
- Аффиксы вообще начинают появляться (следствие §9).

## 11. Проверка

1. `godot --headless --check-only` по `RTLCategory.gd` (у модуля нет `preload`, проверяется
   отдельно).
2. Повторный прогон `tools/probe/simulate_slot_rules.py` против свежего дампа: 32 / 39 / 16,
   список изменений совпадает с §6.
3. Headless-проба реальных ресурсов (`tools/probe/probe_rtl_affixes.gd`): `of_item` даёт
   `weapon` для ножа, `clothing` для сумки, `other` для пластины и ствола; `build_affixes` на
   `ItemData` не падает и для ножа не содержит `recoil`/`fire_rate`.
4. `grep` по `of_path` в `mods/RoadToLoot/*.gd` — пусто.
