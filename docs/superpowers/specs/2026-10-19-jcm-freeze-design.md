# Freeze for JCM — дизайн аддона

Дата: 2026-10-19
Статус: утверждён пользователем (устно, по секциям)

## Цель

Аддон для Juuzoz Cheat Menu (JCM ≥ 3.5.0, addon API 1.0), добавляющий два тумблера на вкладку **AI** меню JCM:

| Тумблер | id | Что замораживает |
|---|---|---|
| Freeze NPC | `jcm-freeze.npc` | Пехота: группы `AI` и `Nomad` — бандиты, охрана, военные, номады, боссы |
| Freeze BTR & Heli | `jcm-freeze.vehicles` | BTR (`BTR.gd`) и вертолёт-ивент (`Helicopter.gd` / `RocketHelicopter.gd`) |

Заморозка — **полностью статичная**: бот замирает в текущей позе, без дыхания и шевелений. Пока тумблер включён, вновь появляющиеся на карте боты замораживаются мгновенно (на первом же кадре). Выключение тумблера оживляет цели.

Не входит в объём (YAGNI):

- снаряды и гранаты в полёте — отдельные узлы, продолжают лететь;
- пулы спавнинга и тумблер «Stop AI From Spawning» — независимые механики JCM;
- зомби и прочая не-AI живность — не в группах, не под `AI.gd`.

## Структура мода

Отдельный проект в репозитории, отдельный `.vmz` (аддон JCM — самостоятельный мод, к «Vostok Toolkit» отношения не имеет):

```
D:\RTVMOD\jcm-freeze\
├── mod.txt
├── pack.ps1
└── jcm-freeze\
    └── Main.gd     ← автолоад
```

`mod.txt`:

```ini
[mod]
name="Freeze for JCM"
id="jcm-freeze"
version="1.0.0"

[dependencies]
required=["juuzoz-jcm"]

[autoload]
jcmFreeze="res://jcm-freeze/Main.gd"
```

Зависимость `required=["juuzoz-jcm"]` заставляет модлоадер не грузить аддон без JCM (и откатить его, если JCM удалён).

## Регистрация в JCM

`Main.gd` следует шаблону из ADDONS.md:

1. `_ready` → ждём `Engine.get_meta("RTVModLib")` (сразу или через `frameworks_ready`).
2. Проверяем `lib.has_mod("juuzoz-jcm")`, наличие узла `/root/jcm`, `has_method("supports_addon_api")` и `supports_addon_api("1.0")`. Не прошло — `push_warning` и выход: старый JCM без API или аддон принудительно загружен без JCM.
3. Регистрируем два тумблера на вкладке `"AI"`:
   - `register_toggle("jcm-freeze.npc", "AI", "Freeze NPC", false, _on_npc_toggled)`
   - `register_toggle("jcm-freeze.vehicles", "AI", "Freeze BTR & Heli", false, _on_vehicles_toggled)`
4. Состояние тумблеров JCM сохраняет в `jcm_settings.ini` и переживает рестарты, а `on_toggled` вызывается только при изменении. Поэтому сразу после регистрации читаем `is_enabled()` обоих тумблеров и, если `true`, выставляем флаги `_npc_on` / `_vehicles_on` — хуки зарегистрированы постоянно и читают флаги, поэтому выставления флага достаточно, никакой «повторной активации» не нужно.

## Механизм заморозки

Хуки регистрируются **один раз** при старте и висят постоянно; в колбэке решает состояние тумблера. Переключение тумблера меняет только булевый флаг — нет гонки «сняли хук, а бот уже заморожен», нет состояния на узлах, переход карты/пул/реактивация `Activate()` ничего не сбрасывают.

### Пехота — `ai-_physics_process-pre`

```gdscript
func _on_ai_process(_delta) -> void:
    if _npc_on:
        _lib.skip_super()
```

Оригинальный `_physics_process` AI.gd (строки 410–426) содержит всю логику: `Detectors/Parameters/Alert/States/Movement/Rotation/Animate/Aiming/Interactor/Voices`. Пропуск метода останавливает и мышление, и движение, и ручное продвижение анимации (у AI анимация продвигается только из `_physics_process` через `animator.advance()` — callback mode ручной), и голоса. Бот замирает статуей в текущей позе.

Мёртвые и неактивные боты этот метод всё равно не выполняют (`if !active: return`, пул держит их с `active=false`) — отдельная фильтрация не нужна.

### Техника — `btr-_physics_process-pre` и `helicopter-_physics_process-pre`

Тот же паттерн с общим флагом `_vehicles_on`. Имена хуков выводятся по правилу «базовое имя скрипта в нижнем регистре + имя метода»; существующий в JCM хук `btr-sensor-post` подтверждает имя для `BTR.gd`. Подтверждение для `Helicopter.gd` — при реализации: `hook()` возвращает `-1` на неизвестном имени.

### Гварды

- каждый `hook()` проверяется на `-1` (паттерн NPCESP); провал логируем через `push_warning`, но аддон не падает — остальные хуки продолжают работать;
- `_lib == null` или нет `skip_super` → предупреждение и выход;
- тумблеры регистрирует сам JCM, поэтому переключение до готовности API невозможно.

## Поведение на карте и известные риски

- **Пехота**: статуя в текущей позе; после выключения тумблера оживает с той же позы (1–2 кадра на втягивание ванильной state-машиной).
- **BTR**: замерает на месте, турель останавливается. Риск: звук двигателя — если это `AudioStreamPlayer3D` на авто-плее, скрипт замолчит, а звук продолжит идти. Проверка в игре; если звучит — при первом срабатывании хука запоминаем `_lib._caller` и глушим его аудио-узлы, пока тумблер включён.
- **Вертолёт**: замерает в воздухе, если его движение из `_physics_process`. Проверка в игре; если падает (ригидбарди) — фолбек: при первом срабатывании хука ловим узел через `_caller` и ставим `process_mode = DISABLED` на корень до выключения тумблера.

## Упаковка и проверка

1. `pack.ps1` внутри `jcm-freeze\` по образцу корневого: чистка `.gd` от построчных `#`-комментариев, пустых строк и CR, упаковка в `Freeze.vmz` (ZIP).
2. Парсинг-стенд: `godot --headless --check-only` по `jcm-freeze/Main.gd` перед сборкой (бинарь из PATH или `tools\4.6.3`).
3. Копия `Freeze.vmz` в папку модов игры `D:\SteamLibrary\steamapps\common\Road to Vostok\mods`.
4. Ручной игровой чек-лист:
   - тумблер Freeze NPC on/off на карте с бандитами: статуя / оживание;
   - свежий спавн при включённом тумблере замораживается без задержки;
   - BTR-ивент: заморозка + проверка звука двигателя;
   - вертолёт-ивент: заморозка в воздухе или фолбек;
   - рестарт игры с включённым тумблером: JCM восстанавливает состояние, аддон продолжает замораживать;
   - смена карты при включённом тумблере;
   - аддон без JCM: модлоадер не грузит (обязательность зависимости).
5. Headless-тестов нет: аддон целиком завязан на рантайм-хуки игры и API JCM, чистой логики, отделённой от рантайма, в нём нечего выделить.

## Версионирование

`1.0.0` в `mod.txt` — первый релиз. Дальнейшие версии по общему правилу репозитория: фича → minor, фикс → patch, несовместимость (смена id тумблеров — сбрасывает сохранённые состояния игроков) → major.
