# Vostok Toolkit 3.0.0 — вкладка «Телепорт» и переименование мода

Дата: 2026-10-03
Статус: утверждён к реализации

## Контекст

Мод называется `Loadouts`, `id="Loadouts-ui"`, папка MCM — `MCM/loadouts`. Изначально он
был про лоадауты, но сейчас содержит: перенос инвентаря, NVG/thermal с подсветкой ботов и
мин, счётчик убийств, ironman со случайным спавном и статами, и — этим релизом — телепорт.

Имя перестало соответствовать содержимому. В папке модов уже есть соседи с префиксом
`Vostok` (`VostokEmissionMCM2`, `VostokRelayChat`), поэтому новое имя продолжает
существующую конвенцию.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Непрочитанные убежища | Показывать все 6, одинаковым видом, без серого и без пометки. `ShelterSave` не создавать |
| Ограничение по открытости | MCM-флаг, по умолчанию **выключен**. Выключен — телепорт в любой; включён — только в открытые, закрытые блокируются |
| Неизвестные трейдеры | Показывать только 3 найденных: Doctor, Gunsmith, Generalist |
| Приземление | Искать землю лучом сверху; при неудаче — смещения по кругу |
| Структура UI | Вкладка в текущей панели мода, внутри три блока |
| Имя мода | `Vostok Toolkit`, `id="vostok-toolkit"` |
| Название вкладки | «Телепорт» (не «Путешествия») |

## 1. Переименование

В `loadouts/mod.txt`:

- `name="Loadouts"` → `name="Vostok Toolkit"`
- `id="Loadouts-ui"` → `id="vostok-toolkit"`

`id` задаёт папку MCM, поэтому после смены настройки и сеты окажутся в
`user://MCM/loadouts`, а мод будет читать `user://MCM/vostok-toolkit`.

**Миграция (разовая, при старте).** Если новая папка отсутствует, а старая есть —
перенести **всё содержимое** папки `user://MCM/loadouts` в
`user://MCM/vostok-toolkit`. Выполняется до `_register_mcm()`, иначе MCM создаст пустую
папку и перенос не сработает. Перенос выполняется ровно один раз; старая папка после него
удаляется.

Переносится папка целиком, а не выборочные файлы: в ней лежат не только `config.ini` и
`loadouts.json`, но и `loadouts.json.bak` с `ui_toggles.json`, о которых легко забыть.
Формат записей не меняется, миграция данных не нужна.

Внутренние имена файлов, папок и автозагрузки (`Loadouts`, `LoadoutsUI`) **не
трогаем** — переименование ради косметики раздуло бы diff и добавило риск сломать
рабочую сборку.

Версия: `2.5.0` → `3.0.0`. По регламенту `AGENTS.md` это несовместимое изменение для
пользователя, ставившего мод по старому имени.

## 2. Новый файл `LoadoutsTravel.gd`

Вся логика телепорта и все данные — в одном месте. `LoadoutsUI.gd` только рисует кнопки
и вызывает методы; правка интерфейса не задевает логику и наоборот.

### Данные

```gdscript
const MAPS := [
	"Village", "Highway", "School", "Outpost",
	"Minefield", "Bridge", "Apartments", "Terminal", "Airfield"
]

const SHELTERS := [
	"Cabin", "Attic", "Classroom", "Tent", "Bunker", "Garage"
]

const TRADERS := [
	{"name": "Doctor",     "map": "School",  "pos": Vector3(46.0, 9.0, 49.0)},
	{"name": "Gunsmith",   "map": "Outpost", "pos": Vector3(106.1, 0.21, -140.0)},
	{"name": "Generalist", "map": "Village", "pos": Vector3(44.9, 0.4, 65.4)}
]
```

Списки карт и убежищ совпадают с `Loader.LoadScene()`. `Template` из списка `Loader`
(`Menu`, `Intro`, `Death`, `Tutorial`, `Template`) в UI не попадает: это служебные
сцены, не карты.

Координаты трейдеров получены из runtime-лога и отражают authored-позиции в зданиях:

- Doctor — `School/Subscenes/School_Classroom_Doctor/Trader/Doctor`
- Gunsmith — `Outpost` (Bunker_A), `Elements/Bunker_Trader/Trader/Gunsmith`
- Generalist — `Village` (Garage_Village), `Trader/Generalist`

### Публичный интерфейс

```gdscript
func travel_to_map(map_name: String) -> void
func travel_to_shelter(shelter_name: String) -> void
func travel_to_trader(entry: Dictionary) -> void
```

Все свойства `gameData`, которых нет в `GameData.tres` по умолчанию (`tutorial`,
`previousMap`, `interface`, `isOccupied`, `playerVector`), читать и писать через
`.get()` / `.set()` с запасным значением, а не прямым обращением. Иначе анализатор и
рантайм споткнутся на свойстве, которого нет.

### Механика

Все три команды сходятся к одной приватной функции
`_teleport_internal(target_map: String, final_offset: Variant)`, чтобы не было трёх копий
логики загрузки сцены. `final_offset` — точка для ручной установки игрока; если `null`,
игрок остаётся там, куда его поставила игра.

Карта и убежище — один и тот же код. Убежище отличается от карты только дополнительной
проверкой, что оно не заблокировано.

Порядок шагов:

1. **Проверка туториала.** Если `gameData.tutorial == true` — вывести
   `loader.Message("Телепорт недоступен в туториале", Color.RED)` и выйти. JCM так делает
   и предупреждает, что телепорт ломает сохранения.
2. **Закрыть интерфейс.** Иначе он останется висеть поверх сцены и будет держать
   ссылки на освобождённые узлы. Закрыть нужно два: ванильный и наш.
   - Наш: вызвать закрытие панели `LoadoutsUI` — она сама и была источником нажатия.
   - Ванильный: если `/root/Map/Core/UI` есть и у него есть `ToggleInterface()` — вызвать
     его. Иначе вызвать `Close()` у `/root/Map/Core/UI/Interface` и сбросить
     `gameData.interface = false`, `gameData.isOccupied = false`.
3. **Определить текущую сцену** по
   `get_tree().current_scene.scene_file_path.get_file().get_basename()` — надёжнее, чем
   читать `gameData.currentMap`.
4. **Сохранить убежище**, если игрок внутри: если `gameData.shelter == true`, вызвать
   `loader.SaveShelter(actual_current_map)`, иначе состояние убежища потеряется.
5. **Синхронизировать карту:** `gameData.previousMap = actual_current_map`,
   `gameData.currentMap = target_map`.
6. **Вызвать** `loader.LoadScene(target_map)`.
7. **Дождаться смены сцены.** `LoadScene` внутри себя ждёт 2 секунды и только затем
   вызывает `change_scene_to_file`, поэтому «подождать пару кадров» после вызова
   недостаточно — сцена ещё даже не начала грузиться.

   1. Запомнить инстанс `get_tree().current_scene` (`get_instance_id()`) **до** вызова
      `LoadScene`.
   2. Опросом `await get_tree().process_frame` ждать, пока `current_scene` станет
      **другим** инстансом. Проверять наличие узлов бесполезно: они есть и в старой
      сцене. Таймаут — 600 кадров, при истечении записать в лог и выйти.
   3. После смены сцены выждать `create_timer(0.1)`, как это делает сам `Loader` в
      `Loader.gd:584`, прежде чем трогать игрока.
8. **Сохранить** `loader.SaveCharacter()` и `loader.SaveWorld()`.
9. **Если `final_offset != null`** — поставить игрока (блок «Механика трейдеров»).

### Механика трейдеров

Если игрок не на карте трейдера, сначала выполняются шаги 1–8. Если уже на нужной карте,
шаг с `LoadScene` не выполняется вовсе, и игрок просто переставляется на месте.

1. Найти живого трейдера поиском по дереву сцены: имя узла равно `entry.name` и скрипт
   заканчивается на `Trader.gd`. Точнее записанных координат. Если не найден —
   использовать `entry.pos`.
2. Выбрать точку в трёх метрах от трейдера по направлению от игрока к трейдеру.
3. Пустить луч вниз с 30 метров. Если поверхность найдена — встать на неё.
4. Поставить игрока: `controller.global_position = point`,
   `controller.velocity = Vector3.ZERO`, `gameData.playerVector = Vector3.ZERO`.

### Узел игрока

Перемещать нужно `/root/Map/Core/Controller`, а не `.../Camera/Manager`. `Controller` —
это `CharacterBody3D` (`Controller.gd:1`), именно его двигает JCM в своём ноклипе
(`controller.global_position += ...`). `Manager` из `Loader.gd:594` — это риг инвентаря
и оружия, к позиции игрока отношения не имеет.

Путь собран из того, что `Controller.gd` использует `rigManager = $"../Camera/Manager"`,
а ванильные скрипты обращаются к `/root/Map/Core/Camera` и `/root/Map/Core/UI` — значит
`Controller` и `Camera` лежат рядом, оба под `Core`. Проверка существования узла
обязательна перед обращением.

## 3. Вкладка «Телепорт» в `LoadoutsUI.gd`

Новая вкладка верхнего уровня «Телепорт». Внутри — узкая полоса из трёх переключателей
`Карты` / `Убежища` / `Трейдеры`; под полосой всегда ровно один видимый блок. Переключение
локальное, пересоздания сцены не происходит. По умолчанию открыт блок `Карты`.

- **Карты** — 9 кнопок, по одной на карту из `MAPS`.
- **Убежища** — 6 кнопок, по одной на убежище из `SHELTERS`. Проверка открытости —
  через `loader.CheckShelterState(name)`, а не вручную через `FileAccess`: так
  состояние определяет сама игра.

  Все 6 убежищ выглядят одинаково, без серого цвета и без пометки «закрыто» —
  сознательное решение, чтобы состояние не подсказывало игроку, какие убежища он
  ещё не открывал. Поведение при нажатии повторяет JCM
  (`JCMActions.gd:teleport_to_shelter`):

  - флаг ограничения выключен (по умолчанию) — телепорт работает всегда, файл
    состояния при этом не создаётся;
  - флаг включён и убежище закрыто — телепорт **не выполняется**, вызывается
    `loader.Message("...", Color.RED)`. Кнопка при этом **не** получает
    `disabled` и **не** меняет вид: отказ сообщается по нажатию, а не заранее.
    Так игрок может нажать и понять причину, вместо того чтобы гадать по
    неактивному элементу. Флаг только влияет на выполнение перехода, но никак
    не на оформление списка.

  Раньше здесь предполагались `disabled = true` и серый цвет, но Godot не
  эмитит `pressed` у заблокированной кнопки — сообщение о блокировке при
  нажатии было бы недостижимо. Решение изменено на вариант JCM.
- **Трейдеры** — 3 кнопки с названием трейдера и картой. Например `Doctor — School`.

Туториал — единственное состояние, при котором кнопки блокируются. Это
повторяет JCM (`JCM_UI.gd`): `disabled = true` плюс текст `Locked (In Tutorial)`.

Если игрок в туториале (`gameData.tutorial == true`), все кнопки всех трёх блоков
отключаются, а подпись получает `— в туториале` — так же поступает JCM, только его
подпись англоязычная. Состояние пересчитывается при каждом открытии вкладки, а не один
раз при загрузке.

`final_offset` передаётся в трёх формах: `null` — игрока не двигать, `Vector3` — поставить
в точку, `Callable` — вызвать после смены сцены. Третий вариант обязателен для трейдеров:
живой узел трейдера появляется в дереве только после загрузки карты, поэтому точку нельзя
считать заранее.

### Новый ключ MCM

Один новый ключ, регистрируется в существующей `_register_mcm`:

| Ключ | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `tp_unlocked_shelters_only` | Bool | `false` | Разрешить телепорт только в открытые убежища |

`false` — поведение по умолчанию из принятых решений, то есть показываем всех и
телепортируем в любой. Флаг существует как выход для тех, кому нужно ограничение.

`_register_mcm` синхронизирует `config.ini` по ключам, поэтому добавление ключа
безопасно, а его последующее удаление из кода само собой почистит конфиг — отдельный
мажорный релиз для этого не нужен.

При открытии вкладки интерфейс уже ставит игру на паузу; поведение паузы и захвата
мыши не меняется.

## Отказы

| Ситуация | Поведение |
|---|---|
| Игрок в туториале | `loader.Message(...)`, выход. Кнопки в UI отключены заранее |
| Нет `/root/Loader` | Запись в лог, выход без ошибки |
| Убежище заблокировано и включён соответствующий флаг | Сообщение, выход |
| `LoadScene` не сменил сцену за 600 кадров | Запись в лог, выход |
| Нет `/root/Map/Core/Controller` | Запись в лог, выход |
| Трейдер не найден в дереве | Использовать записанные координаты |
| Земля не найдена лучом | Пробовать смещения по кругу: 6 точек на расстояниях 2, 4, 6 м |
| Земля не найдена даже после смещений | Поставить как есть, записать координаты в лог |

Интерфейс не падает ни в одном из случаев. После телепорта показывать
`loader.Message("Телепорт: <цель>", Color.GREEN)` — пользователь должен видеть, что
действие сработало.

## Образец: JCM

Механика сверена с модом `D:\RTVMOD\referens\JCM.vmz` (`Juuzoz Cheat Menu` 3.1.0) —
он тоже даёт телепорт по картам и убежищам. Оттуда взяты: проверка туториала, закрытие
интерфейса перед переходом, `SaveShelter` перед выходом из убежища, синхронизация
`previousMap`/`currentMap`, вызовы `SaveCharacter`/`SaveWorld`, `CheckShelterState` для
проверки блокировки и `loader.Message` для обратной связи.

Отличия от JCM: у него 8 карт и нет `Minefield` (хотя `Loader.LoadScene` его
поддерживает) — у нас 9, вместе с `Minefield`. Список убежищ у обоих совпадает.
Трейдеров нет ни у кого из нас — это новая функциональность.

## Вне области

- Hunter, Driver, Grandma в список трейдеров **не входят**.
- `Template`, `Menu`, `Intro`, `Death`, `Tutorial` в UI не показываются.
- Жёстких путей к трейдерам в коде нет — только имя и карта.
- Поведение ironman (случайный спавн и случайные статы) не меняется.
- `tonemap_exposure` не переопределяется.

## Проверка

1. `powershell -NoProfile -ExecutionPolicy Bypass -File "D:\RTVMOD\.check\check.ps1"` —
   6 файлов `.gd`, все должны пройти.
2. Миграция MCM: положить набор в `MCM/loadouts`, запустить, убедиться, что он
   появился в `MCM/vostok-toolkit` и сет читается.
3. Телепорт на каждую из 9 карт.
4. Телепорт в каждое из 6 убежищ, включая закрытое.
5. Проверить MCM-флаг `tp_unlocked_shelters_only`: выключен — телепорт в закрытое
   убежище работает; включён — кнопка заблокирована и выводится сообщение.
6. Телепорт к каждому из 3 трейдеров, включая вариант с карты, отличной от карты
   трейдера. Проверить, что игрок стоит на земле, а не в воздухе или стене.
7. Один раз проверить, что во время туториала кнопки заблокированы.
