# Picker: сетки, обвесы-плитки, подкатегории — Design

**Дата:** 2026-10-05
**Версия:** 4.5.0 → 4.6.0
**Статус:** утверждён

## Проблема

Пять наблюдений из игры:

1. Сетка шага 1 показывает 5×2 при гораздо большей видимой области, со полосой
   прокрутки. Сетка шага 2 — 4×2, тоже при большей области.
2. Для слота `Primary` видны три категории (Оружие / Рыбалка / Инструменты)
   отдельными полками. Нужен фильтр чипами под «Цель:».
3. Пункт «Все предметы» на шаге 1 лишний.
4. Чтобы надеть обвесы, надо кликнуть по названию слота в левой колонке —
   неочевидно. И выбранный обвес не отличается от невыбранного: при наведении
   серая, при нажатии чёрная, после нажатия ничего не остаётся.
5. Нет локализации `Rig`, «Бронежилет» и прочих подкатегорий.

## Диагноз

**Сетка шага 1.** `VTKUI.gd:591` — `shelves_scroll.custom_minimum_size =
Vector2(0, 240)`. Высота зашита в 240 px, при высоте клетки 110 влезает ровно
два ряда, дальше прокрутка. По ширине `HFlowContainer` считает сам: клетка 80 px
плюс `h_separation` 4, в отведённую ширину влезает пять.

**Сетка шага 2.** `VTKUI.gd:639` — `_gear_grid.columns = 4`. Буквальная
константа, ширина окна на неё не влияет.

**Состояние обвеса.** `_make_att_toggle` (`VTKUI.gd:1782`) задаёт только стиль
`normal`. Godot рисует `hover`, `pressed` и `focus` из темы, и они перебивают
`_make_chip_style(on)`: серый при наведении, чёрный при нажатии.

**Вход в обвесы.** Панель открывается только по кнопке в строке слота
(`_make_att_btn`, `VTKUI.gd:1444`), то есть через узкое место.

## Решение

### Сетки: колонки от ширины, высота без ограничения

Оба шага получают одинаковое поведение, иначе они снова разъедутся.

- `custom_minimum_size` по вертикали убирается у `shelves_scroll`
  (`VTKUI.gd:591`) и `_gear_grid_scroll` (`VTKUI.gd:636`).
- Оба получают `size_flags_vertical = SIZE_EXPAND_FILL`.
- Вместо константы `_gear_grid.columns = 4` — пересчёт:

  ```
  columns = max(1, floor((width + h_sep) / (cell_w + h_sep)))
  ```

  Пересчёт вешается на `resized` сетки: на первом показе ширина ещё нулевая,
  и без обработчика получится одна колонка.
- Полка шага 1 (`HFlowContainer` внутри `_make_shelf`) получает
  `size_flags_vertical = SIZE_EXPAND_FILL`, иначе высота схлопнется к одной
  строке.

Один `_make_grid_columns(width) -> int` на оба шага. Размер клетки остаётся
80×110.

### Шаг 1: «Цель» и строка фильтров

`_target_bar` (`VTKUI.gd:572`) становится двумя строками:

```
Цель: Primary
Фильтр: [Оружие] [Винтовки] [Снайперки] [Пистолеты] [Сброс]
```

- Чипы верхнего уровня — категории, подходящие слоту.
- Выбор категории раскрывает её подкатегории следом в той же строке.
- `[Сброс]` снимает и категорию, и подкатегорию. Каталог снова показывает все
  предметы, подходящие слоту. Чип виден всегда, при пустом фильтре приглушён.
- Пункт «Все предметы» с шага 1 уходит: для экипировки смотреть всё не нужно.
- Клик по строке слота в левой колонке только выбирает цель. Обратного клика
  для сброса нет — вариант «повторный клик по слоту снимает подкатегорию»
  признан хрупким: цель и фильтр должны быть независимы.

### Обвесы: вход из клетки и плитки вместо чипов

Клик по предмету в сетке кладёт его в слот-цель **и** открывает панель обвесов
для него. Заголовок панели — «Обвесы» вместо `Target: <имя>`: панель открыта
ровно под тем предметом, который только что выбран, и имя в заголовке
дублирует клетку.

Панель переезжает из-под сетки в правую часть шага, где сейчас
`_gear_att_box`, и тянется по высоте.

`_make_att_toggle` заменяется на плитку 80×110 с иконкой и именем —
переиспользуется `_make_item_cell` (`VTKUI.gd:1469`) с флагом выбора.
Выбранный обвес — золотая рамка, та же, что у предмета в сете.

Побочный эффект: баг с темой уходит вместе с `_make_chip_style`, потому что у
плитки задаются все четыре стиля явно.

У обоймы вместо списка обвес по-прежнему тумблер полной обоймы. Он не плитка и
остаётся отдельным.

### Категории и подкатегории

Источник таксономии — `referens/JCM_x/mods/JCM/JCMDatabase.gd`, заголовки
`-- X --`. 41 подкатегория; `FURNITURE` не берём (там `res://Assets/...`, не
предметы для сета).

| Константа JCM | Подкатегории |
|---|---|
| `PRIMARY_WEAPONS` | Assault Rifles, Sniper Rifles, Shotguns |
| `SECONDARY_WEAPONS` | Pistols, SMGs |
| `MAGAZINES` | Handgun & SMG Mags, Rifle & Sniper Mags |
| `AMMO` | Pistol & SMG Calibers, Rifle Calibers, Shotgun Shells |
| `MEDICAL` | First Aid, Medication, Hygiene & Utility |
| `GEAR` | Helmets & Night Vision, Armor Plates, Rigs & Vests, Backpacks, Belts, Knives, Grenades, Hats, Torso, Pants, Boots & Hands |
| `ATTACHMENTS` | Weapon Parts, Optics, Lasers & Suppressors |
| `FOOD` | Hydration, Canned Goods, Snacks & Ingredients, Cooked Meals, Vices, Fish |
| `KEYS` | Shelter Keys, Lootroom Keys |
| `MISC` | Electronics, Utilities & Tools, Survival, Books, Music & Fishing, Lore |

**Ключ подстановки — папка, не путь.** Второй сегмент не годится: `Weapons`
встречается семь раз. Третий сегмент различает: `Weapons/AKM/AKM.tres` → `AKM`
→ Assault Rifles. Таблица содержит имена папок, а не пути в игру, поэтому
переживает апдейт — предупреждение `AGENTS.md` про жёсткие пути не нарушается.

**Приоритеты разрешения.** Извлечение из JCM показало три коллизии, их
разрешает порядок правил:

1. Магазин определяется именем файла: `*_Magazine.tres`, `*_Mag.tres`,
   `*_Drum.tres` → Handgun & SMG Mags или Rifle & Sniper Mags по семейству
   ствола. Это снимает коллизию `Makarov`, который и в Pistols, и в
   Handgun & SMG Mags.
2. `*_Barrel.tres` и прочие части ствола → Weapon Parts. Это снимает коллизию
   `KAR-21`: ствол в Assault Rifles, ствольная коробка в Weapon Parts.
3. Иначе — папка по таблице из третьего сегмента.
4. Иначе — имя папки как есть: `Fishing/Bream` → «Рыба`,
   `Instruments/Guitar` → «Гитара».

Молчаливого «без категории» не остаётся ни на одном шаге.

**Трёхсегментные пути.** У части предметов папки нет: `Items/Armor/Armor_Plate_II.tres`.
Такие разбираются вторым сегментом:

| Путь | Подкатегория |
|---|---|
| `Items/Armor/Armor_Plate_II.tres` | Armor Plates |
| `Items/Armor/Armor_Plate_IV.tres` | Armor Plates |
| `Items/Keys/Key_Attic.tres` | Shelter Keys |
| `Items/Keys/Key_Bunker.tres` | Shelter Keys |
| `Items/Keys/Key_Classroom.tres` | Shelter Keys |
| `Items/Keys/Key_Garage.tres` | Shelter Keys |
| `Items/Keys/Key_Cellar.tres` | Lootroom Keys |
| `Items/Keys/Key_Gymnasium.tres` | Lootroom Keys |
| `Items/Keys/Key_Tunnel.tres` | Lootroom Keys |
| `Items/Books/Book_Children.tres` | Books |
| `Items/Books/Book_Cooking.tres` | Books |
| `Items/Books/Book_Fishing.tres` | Books |
| `Items/Books/Book_Religion.tres` | Books |

Правило: путь из трёх сегментов (`Items/<папка>/<файл>`) читается по второму
сегменту, из четырёх и больше — по третьему. Проверка длины, а не угадывание:
`Keys/Key_Tunnel.tres` и `Keys/Sub/Key_Tunnel.tres` должны давать разный ответ.

`Picker.subcategory_of(path, type) -> String` едет в `VTKPicker` рядом с
`category_of` и `facets_of` — чистая строковая функция, тестируется headless.
Шаг 2 показывает подкатегории вторым уровнем фасетов.

### Локализация

Ключи для перевода выводятся из готовой таблицы подкатегорий, а не
придумываются заранее: сначала задача с `subcategory_of` и полной таблицей,
затем прогон скрипта, печатающего все ключи, и только из его вывода пишется
`RU`. Ни один заголовок не потеряется молча; `keycheck.py` проверяет
результат.

Имена предметов не переводятся — как договорились: они приходят из `Database`
и используются как есть.

## Влияние на существующий код

| Символ | Что |
|---|---|
| `VTKUI.gd:591` | убрать `custom_minimum_size` по вертикали |
| `VTKUI.gd:636` | то же |
| `VTKUI.gd:639` | `_gear_grid.columns = 4` заменить пересчётом |
| `VTKUI.gd:572` | `_target_bar` становится строкой «Цель» + строкой фильтров |
| `VTKUI.gd:1770` | `_make_att_toggle` заменяется плиткой |
| `VTKUI.gd:1742` | заголовок `Target: ` → `Attachments` |
| `VTKUI.gd:1444` | `_make_att_btn` остаётся только для обоймы |
| `VTKPicker` | новая `subcategory_of` + таблица подкатегорий |

`_make_chip_style` остаётся в файле для строк фасетов и слотов — он не
удаляется, его просто перестаёт использовать панель обвесов.

## Проверка

- `python .check\layout_check.py` — символы раскладки; новые в `PRESENT`:
  `_make_grid_columns`, `subcategory_of`; в `GONE` ничего не добавляется.
- `powershell -NoProfile -ExecutionPolicy Bypass -File .check\check.ps1` —
  парсинг 9 скриптов и тесты.
- `python .check\keycheck.py` — все новые ключи в `RU`.
- `python .check\encoding_check.py` — `pack version: 4.6.0`, `PROBLEMS: 0`.
- Тесты `test_picker.gd` пополняются на `subcategory_of`: магазин по суффиксу,
  ствольная коробка в Weapon Parts, неизвестная папка, трёхсегментный путь,
  гранаты по `Grenade_*`.

Ручная проверка в игре:

1. Шаг 1: сетка занимает всю высоту, колонок больше пяти, полоса прокрутки
   появляется только когда содержимое не влезает.
2. Шаг 1: строка «Фильтр» с чипами, `[Сброс]` возвращает все предметы слота,
   слот остаётся `Primary`.
3. Шаг 2: сетка 4 колонки больше не захардкожена, считается от ширины.
4. Клик по AKM кладёт его в `Primary` и открывает «Обвесы» с плитками.
5. Выбранный обвес остаётся золотым после того, как курсор ушёл.
6. Обвес снимается вторым кликом, а не требует переоткрытия панели.
7. Шаг 2: подкатегории «Винтовки», «Снайперки», «Пистолеты» в фасетах.
8. RU: `Rig`, «Бронежилет», «Оптика» переведены.

## Что не делаем

- Не трогаем другие вкладки (`Sets`, `Settings`, `Teleport`).
- Не переводим имена предметов.
- Не меняем формат `VTKsets.json`: версия 4.6.0 — MINOR, обратная совместимость
  сохранена.
- Не хардкодим пути в игру.
