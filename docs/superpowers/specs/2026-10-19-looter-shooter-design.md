# LooterShooter — дизайн

Дата: 2026-10-19
Статус: approved (дизайн), ожидает плана реализации
Мод: `LooterShooter` (префикс скриптов `LSH`), отдельный самодостаточный мод

## 1. Цель

Добавить в Road to Vostok слой «лутер-шутера»: находки в контейнерах и на трупах получают
**редкость экземпляра** и набор **пассивных бонусов**. Два одинаковых ствола из разных ящиков
могут оказаться совершенно разными по силе — это главный источник повторного интереса к луту.

Целевой опыт:

- игрок узнаёт хорошую вещь по цвету рамки и читает её бонусы в тултипе;
- прокачка не обязана быть, лут-петля самодостаточна;
- ничего ванильного не ломается: редких предметов не становится больше, износа/экономики не
  касаемся, торговцы и стартовый инвентарь — ванильные.

## 2. Утверждённые решения

| # | Решение | Обоснование |
|---|---|---|
| D1 | Редкость — **по экземпляру**, не по типу | два одинаковых предмета = разный ролл |
| D2 | **Отдельный мод**, не фича Vostok Toolkit | другой объём, своя версия, свой цикл обновлений |
| D3 | Пул пассивок = существующие статы + реген ХП | без новых боевых систем; вампиризм/стихии/проки исключены |
| D4 | Схема A: Ванильный 0 / Обычный 1 / Редкий 2 / Легендарный 3 аффикса | читаемо, контролируемо |
| D5 | Источники ролла фазы 1 — **только находки** (контейнеры, трупы) | торговцы/задания/старт остаются ванильными |
| D6 | Обвесы — **вне фазы 1** | аффиксы во вложенном `slotData.nested` — отдельная возня |
| D7 | Сеты — **следующая веха** | не строим сейчас, архитектуру не запираем |
| D8 | Хранение — **override `SlotData.gd`** (`[script_extend]`) | поля едут с предметом через все пути сейва |
| D9 | Значения — **итоговые брошенные числа**, не «×множитель» | ребаланс пула не переписывает старые предметы |
| D10 | Отображение: рамка ячейки по тиру + блок аффиксов в тултипе | вариант A; MCM-тумблеры |
| D11 | Ванильная строка редкости (`ItemData.rarity`) остаётся, качество — **своей отдельной строкой** | две разные оси, не прячем ванильную информацию |
| D12 | Палитра: Обычный — синий, Редкий — фиолетовый, Легендарный — золотой | своя, не ванильные GREEN/RED/DARK_VIOLET |
| D13 | Слот хранения — **исключён** | без GSE ему негде жить |
| D14 | Оружейные статы — **per-instance через чтение в момент потребления**; мутация общего `WeaponData` только как fallback | ваниль хранит урон/отдачу в общем ресурсе на тип |

## 3. Раскладка и компоненты

Стандарт standalone-мода этого репозитория (как `standalone mods/ThermalVTK/`):

```
standalone mods/LooterShooter/
├── mod.txt                     # [mod] name/id/version, [autoload] LSHBoot, [dependencies] MCM optional
├── pack.ps1                    # сборка LooterShooter.vmz
├── LooterShooter.vmz           # артефакт
├── README.md                   # предупреждение о сейвах, совместимость, дебаг-режим
├── CHANGELOG.md                # для игроков, английский
└── mods/LooterShooter/
    ├── LSHBoot.gd              # автолоад: инициализация, регистрация хуков, ре-скан
    ├── LSHConfig.gd            # типизированный срез MCM-конфига
    ├── LSHPool.gd              # данные пула аффиксов (статы, категории, диапазоны, веса)
    ├── LSHRoll.gd              # чистая математика ролла (тир, выбор аффиксов, значения)
    ├── LSHCategory.gd          # resource_path -> категория (weapon/clothing/other), чистая
    ├── LSHStore.gd             # единственное место чтения/записи loot_tier/loot_affixes
    ├── LSHStats.gd             # агрегация надетого в {stat: total}, чистая
    ├── LSHApply.gd             # аппликаторы статов (точки потребления)
    ├── LSHDisplay.gd           # оверлеи ячеек + блок тултипа
    ├── LSHDebug.gd             # force tier, реролл под курсором, лог
    └── Scripts/SlotData.gd     # override базового Scripts/SlotData.gd
```

Поток: `LootContainer.CreateLoot` post-хук → `LSHRoll` → `LSHStore` пишет на `SlotData` →
смена экипировки → `LSHStats` пересчёт → `LSHApply` потребляет → `LSHDisplay` рисует.

Разделение по тестируемости: чистые модули (`LSHPool`, `LSHRoll`, `LSHStats`, `LSHCategory`,
`LSHConfig`) без `load()` и путей внутрь игры — покрываются headless; всё, что знает про игровые
узлы, живёт в `LSHBoot`/`LSHApply`/`LSHDisplay`.

## 4. Данные экземпляра

`Scripts/SlotData.gd` (override расширяет ванильный):

```gdscript
@export var loot_tier: int = 0        # 0=Ванильный, 1=Обычный, 2=Редкий, 3=Легендарный
@export var loot_affixes: Array = []  # [{"stat": "recoil", "value": 0.12}, ...]
```

`Update()` ванильного `SlotData` копирует ровно 16 полей — override зовёт `super()` и копирует
оба поля после него. `LSHStore` — единственная точка доступа к этим полям (остальной код не знает
имён свойств).

Значения — итоговые числа: процент пишется как доля (`0.12` = 12%), реген как HP/сек, груз в кг,
пробитие/защита как плоско.

## 5. Пул аффиксов

Формат записи в `LSHPool.gd`: `{stat, category (weapon|clothing), ranges_per_tier, unit, weight}`.
Тир задаёт границы при ролле, не множит их вслепую.

### Оружие

| stat | Обычный | Редкий | Легендарный |
|---|---|---|---|
| `damage` +% урона | 5–15 | 10–20 | 15–30 |
| `recoil` −% отдачи | 8–15 | 12–22 | 18–30 |
| `sway` −% качания | 10–20 | 15–30 | 20–40 |
| `fire_rate` +% скорострельности | 5–10 | 8–14 | 10–20 |
| `penetration` +пробитие | — | +1 | +1–2 |
| `low_hp_damage` +% урона при ХП<30% | 15–25 | 25–35 | 35–50 |
| `durability` −% износа | 25–40 | 40–55 | 55–75 |

### Одежда

| stat | Обычный | Редкий | Легендарный |
|---|---|---|---|
| `max_hp` +макс. ХП | 5–10 | 10–20 | 15–50 |
| `regen` реген HP/сек | 0.01–0.02 | 0.02–0.05 | 0.04–0.08 |
| `low_hp_regen` реген при ХП<30% | ×2 | ×2.5 | ×3 |
| `carry` +грузоподъёмность, кг | 2–5 | 5–8 | 8–10 |
| `stamina_drain` −% расхода стамины | 8–15 | 12–22 | 18–30 |
| `insulation` +% изоляции | 10–20 | 20–30 | 30–40 |
| `noise` −% шума | 10–20 | 15–30 | 20–40 |
| `sprint` +% скорости бега | 3–6 | 5–9 | 8–12 |
| `protection` +защита (плоско) | — | +1 | +1 |
| `thirst_drain`/`hunger_drain`/`sanity_drain` −% расхода | 8–15 | 12–22 | 18–30 |

Исключено сознательно: вампиризм, отражение урона, стихийные резисты/урон, «Indestructible»,
проки-способности, +слот хранения.

## 6. Ролл

**Точка:** post-хук `LootContainer.CreateLoot` (ваниль создаёт `SlotData`, кидает amount/condition,
кладёт в `loot`). Post читает контекст через `_caller`, берёт `loot.back()`, через `LSHStore`
пишет тир и аффиксы.

**Фильтр:** только категории оружие и одежда. Еда/патроны/инструменты/расходники не роллятся.
Квестовые оружие и одежда роллятся наравне — фильтр по категории, не по «квестовости».

**Распределение тиров** (веса Van/Common/Rare/Legendary), опирается на контекст контейнера
(ванильный `rarityRoll`, посчитанный в `GenerateLoot`; точные значения сверить при реализации):

| Контекст | Van | Common | Rare | Leg |
|---|---|---|---|---|
| обычный контейнер | 60 | 30 | 9 | 1 |
| редкий контейнер | 35 | 40 | 20 | 5 |
| corpse | 45 | 35 | 15 | 5 |
| full loot / joker | 15 | 35 | 35 | 15 |

Множитель частоты редкостей (MCM `Balance`) масштабирует веса вниз/вверх (×0.5 / ×1 / ×2).

**Выбор аффиксов:** N штук по тиру, без повторов одного `stat`, взвешенно из пула категории,
диапазон по тиру. Список взаимоисключений заводится полем данных и пока пуст.

**Дебаг-режим** (MCM-категория `Debug`, по умолчанию выключен):
- `Force tier: Off / Vanilla / Common / Rare / Legendary` — все находки принудительно этого тира;
- хоткей `reroll hovered item` — пересобирает тир и аффиксы предмета под курсором;
- строка в лог на каждый ролл (предмет, тир, аффиксы).

## 7. Применение пассивок

Аффиксы действуют **только когда предмет надет**; в рюкзаке и в контейнере спят.
`LSHStats` агрегирует надетое в `{stat: total}`; пересчёт по событиям
(`interface-equip`/`unequip`/`fastequip`/`contextunequip`, `loader-loadcharacter-post`,
`compiler-spawn-post`) плюс страховочный ре-скан раз в ~60 кадров.

Кандидатные точки потребления (по следам Evolve / XP & Skills; точные сигнатуры и арности
подтверждаются тестом арностей на стенде, как `t_post_callback_arity` у VTK):

| Стат | Точка | Прецедент |
|---|---|---|
| `regen`, `low_hp_regen` | `character-_physics_process` post | Evolve / XP-Skills |
| `max_hp` | `character-clamp` (replace) | Evolve |
| `stamina_drain` (руки/тело) | drain pre/post, дельта через meta | Evolve |
| `thirst_drain`/`hunger_drain`/`sanity_drain`/температура | drain-хуки | Evolve |
| `carry` | `interface-updatestats` post + overweight | Evolve |
| `noise` | `sensor-playerheardetection` (replace) | Evolve |
| `insulation` | `interface-updatestats` / путь `FreezeSpeed` | Evolve |
| `durability` | точка уменьшения `condition` | найти при реализации |
| `damage`, `low_hp_damage`, `fire_rate`, `recoil`, `sway`, `penetration` | боевой путь `WeaponRig` (чтение агрегата в момент выстрела) | Evolve (отдача — мутацией) |

**Принцип per-instance (D14):** ваниль держит урон/отдачу в `WeaponData` — общем ресурсе на тип.
Бонус читается в момент потребления из агрегата надетого ствола, тогда он принадлежит экземпляру и
снимается сам при смене оружия. Если конкретный стат в боевом пути не перехватывается (например,
гейт скорострельности — локальная переменная), применяется точечная мутация ресурса с кэшем базы в
`meta` и восстановлением на unequip — с оглядкой на `RealGunAndAttachmentNames` (трогает свойства
`WeaponData`).

Защита (+1) вмешивается в int-сравнение пробития — следить за балансом.

## 8. Отображение и MCM

**Рамка ячейки:** оверлей-Panel поверх ячейки (приём ItemClarity: перехват `node_added` + первичный
обход дерева; идемпотентно по имени `_lsh_border`; `StyleBoxFlat` без текстур). Цвет по тиру:
Обычный синий, Редкий фиолетовый, Легендарный золотой. Пустые ячейки не трогаем. При конфликте с
ItemClarity/LootHighlight оверлей выключается тумблером.

**Тултип:** post-хук `tooltip-update-post`. Ванильная строка редкости остаётся; ниже отдельный блок
`LSHAffixBlock`: строка качества цветом палитры + строки аффиксов (`+12% damage`, `+0.03 HP/s`,
`+5 kg`). Блок идемпотентен — старый сносится перед вставкой, строки не копятся.

**MCM-секция `LooterShooter`** (мод грузится последним, `priority=-100`, MCM — optional-зависимость):
- `Display`: «Красить ячейки», «Показывать блок аффиксов»;
- `Balance`: множитель частоты редкостей ×0.5 / ×1 / ×2;
- `Debug`: force tier, хоткей реролла.

**Локализация:** английские литералы (язык игры). RU-перевод — отдельным проходом, если появится
`LSHLoc`.

## 9. Сохранения и совместимость

- Два поля едут в `Character.tres`, storage приютов, `ItemSave`. Без мода Godot варнит
  `property not found` и дропает значения → README: «не удалять мод из существующего сейва».
- Аудит ~20 мест `SlotData.new()` (Interface, LootContainer, Trader:148, Task:68/84, AI:277):
  там, где копирование идёт мимо `Update()` (стек-сплит, торговец, Task), поля могут не донестись —
  закрыть своим хуком.
- Пересекающиеся статы с Evolve / XP & Skills (отдача, макс. ХП, реген, груз) складываются — это
  ожидаемо для RPG-слоя, фиксируем в README.
- Лут-пайплайн моды (Lootopia, ExtraSpecialCrates, AIActuallyLoots, LootHighlight) — проверка
  сосуществования вручную; наш post-хук от их логики не зависит.
- Мультислоты (MultiSaveSlotsReborn) — сейвы идут через те же пути Loader, проверить в игре.
- GSE — `slotData.storage` не трогаем.

## 10. Тесты

Стенд `.check` (копирует `mods/LooterShooter/*.gd`, headless `--check-only` + прогон тестов):

- `test_lsh_roll.gd` — распределение весов, контексты, чистота от недетерминизма (seed);
- `test_lsh_stats.gd` — агрегация, суммирование, границы;
- `test_lsh_pool.gd` — валидность данных: диапазоны на все тиры, категории, веса;
- `test_lsh_category.gd` — `resource_path` → категория;
- `test_lsh_config.gd` — типизированный срез MCM;
- `test_lsh_slotdata.gd` — `Update()` копирует поля (на стабах);
- `test_lsh_arity.gd` — арности наших post-колбэков (void vs не-void).

Ручной чек-лист в игре: дроп (лог), тултип, рамки, реген, урон/отдача, save/load, storage приюта,
сплит стека, дебаг-реролл, сосуществование с Evolve/ItemClarity.

## 11. Риски

| Риск | Митигация |
|---|---|
| override `SlotData.gd` теряет поля на части путей копирования | аудит `SlotData.new()`, свой хук; тест на стабах |
| гейт скорострельности не перехватывается | fallback-мутация `WeaponData` с кэшем базы |
| flat `+protection` слишком силён | следить по игре, при необходимости только Легендарный |
| ванильные значения `rarityRoll` иные, чем в таблице | сверить при реализации, веса живут в `LSHPool` |
| чужие оверлеи ячеек (IC/LootHighlight) накладываются | тумблер выключения раскраски |

## 13. Вне объёма
