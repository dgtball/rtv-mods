# Превью набора и Done: три колонки с управлением — дизайн

Статус: **предложено, ждёт ревью пользователя**.

## Проблема

Превью выбранного сета собрано из разрозненных блоков: шапка с именем и
хоткеем-подписью, слева панель экипировки (ниже стены инвентаря на ~113px),
справа стена 581×581, под всем этим — отдельная строка кнопок. Итог:
пустота правее стены и ниже экипировки, хоткей виден дважды (в шапке и в
кнопке), а шапки («Экипировка · имя», «Инвентарь · N слоёв») выглядят
документацией, а не оформлением. Раздел «VOSTOK TOOLKIT» (имя + версия
столбиком слева) тоже минималистичен до скучности.

Страница Done черновика использует тот же билдер превью и получает те же
блоки (плюс свою строку имени/хоткея и кнопки Сохранить/Отмена).

## Решение

Превью и Done переходят на **три колонки**: Экипировка | Инвентарь |
Управление. Колонка Управление тянется на всю высоту и принимает кнопки
действий — пустота справа и внизу закрыта. Тот же билдер колонок (с
другим набором кнопок) собирает страницу Done. Раздел «VOSTOK TOOLKIT»
получает плашку и версию справа.

Решение подтверждено макетами в визуальном компаньоне: вариант A (колонка
Управление справа на всю высоту), D2 (Done: имя своей строкой над карточкой),
рейл «плашка V + имя, версия справа».

### Раскладка превью (draft == null, `_refresh_preview`)

```
┌─ имя набора ── подпись «Раскладка · N предметов» ────────┐
│ ┌─Экипировка─┐ ┌────────Инвентарь────────┐ ┌─Управление─┐ │
│ │ сетка 6×8  │ │     стена 8×8 581×581    │ │ Применить   │ │
│ │ (неклик)   │ │                          │ │ Изменить    │ │
│ │            │ │                          │ │ R·F6 / ?    │ │
│ │            │ │                          │ │ Удалить     │ │
│ └────────────┘ └──────────────────────────┘ └────────────┘ │
└────────────────────────────────────────────────────────────┘
```

- Card-шапка: имя набора (кремовое `#d8cdbe`, 14px; макет `.cname`) +
  подпись «Раскладка · N предметов» (9px, капс, `#5f5347`; макет `.cmeta`).
  Сейчас имя рисуется `_gold` (584–585) — цвет меняется на кремовый.
  Хоткей-подпись из шапки **убрана** — клавиша живёт только в кнопке колонки
  Управление. Хоткей-бейдж в макете (`.seth .tag`) — только в списке сетов, не в превью.
- Три колонки в `HBoxContainer`, каждая панель `SIZE_EXPAND_FILL` по
  вертикали: нижние края всех трёх вровень, при росте стены (>64 стека)
  колонки растут вместе с ней.
- **Экипировка**: шапка «Экипировка» (`_gold`, 9px, капс, как `.mhd` в макете;
  сейчас заголовок колонки `#5f5347` — меняется на `_gold`), ниже прежняя
  некликабельная сетка `_make_equip_grid(cells, cols, rows, eq, false)`,
  прижатая к верху.
- **Инвентарь**: шапка «Инвентарь» (`_gold`, 9px, капс), ниже
  `_make_inventory_wall`. Счётчик из шапки панели **убирается** — уезжает в
  подпись карточки (макет full-page-v2 всё ещё несёт `· 12 · сетка 8` в `.mhd`
  Инвентаря — это не по решению, спека берёт верх).
- **Управление**: шапка «Управление», ниже вертикальный стек кнопок
  (полная ширина, по центру высоты): **Применить** (акцент),
  **Изменить**, **клавиша** (`F6`/`R` золотом, `?` — серым, либо
  «Назначить клавишу» — как `qk_btn` сейчас), **Удалить**
  (красноватый, текстом вместо «✕»). Всё — прежние обработчики:
  `LD.load_loadout`, `_edit_loadout`, `_begin_bind`, `_delete_loadout`.

`_build_set_preview(title, eq, gear, fill)` отдаёт каркас: карточку с тремя
колонками **и с уже переданной готовой колонкой управления** (кнопки
собирает вызывающий и передаёт параметром `controls: Control`). Шапка
карточки живёт у вызывающего: превью — в `_refresh_preview`, Done — в
`_refresh_page_done`. Заголовок колонки экипировки больше не несёт имени
сета (`_make_equip_preview` получает «Экипировка» вместо
`Equipment · <name>`).

### Раскладка Done (draft != null, `_build_page_done`)

Вариант D2:

```
Экипировка · Снаряжение · Done      ← шаги, без изменений
Имя: [             ]  Клавиша: [R ▾]
┌─Экипировка─┐ ┌─Инвентарь─┐ ┌─Управление─┐
│  сетка 6×8 │ │  стена    │ │ Сохранить   │
│            │ │           │ │ Отмена      │
└────────────┘ └───────────┘ └────────────┘
```

- Строка имени и хоткея (`_build_page_done:1483-1518`) остаётся над
  карточкой; под именем добавляется подпись «Раскладка · N предметов»
  (счётчик сюда, см. Локализация).
- Карточка ниже — те же три колонки одним билдером. Управление: **Сохранить
  сет** + **Отмена** (прежние `_save_loadout`, `_cancel_draft`).

### Раздел «VOSTOK TOOLKIT» (`_build_ui`, 432–460)

```
[V] VOSTOK TOOLKIT                    v 4.12.1
```

- Слева плашка «V» (26×26, `StyleBoxFlat`, заливка `#d48a3a`, скругление 4,
  буква 13px, `#0e0b08`).
- Имя «VOSTOK TOOLKIT» — 11px, кремовое, капс (как сейчас), версия **под
  именем убирается**: столбик name_box схлопывается, версия уезжает вправо
  (9px, `#5f5347`) через `size_flags_horizontal = SIZE_EXPAND_FILL` у спейсера.
- Никаких других надписей справа («Loadouts · ESP · Teleport» из макета в
  код не берём — ключей и смысла нет).

## Локализация

Правило «английский — исходный язык»: ключ словаря сам является английской
строкой, отсутствующий перевод деградирует до читаемого английского.

Новые ключи в `VTKLoc.gd`:

- `'Controls': 'Управление',`
- `'Delete': 'Удалить',`
- `'Loadout': 'Раскладка',` — слово подписи карточки.
- `' items': ' предметов',` — с ведущим пробелом, как `' items · '`.
  Подпись карточки строится так:
  `Loc.txt("Loadout") + " · " + str(n) + Loc.txt(" items")`
  → «Раскладка · 12 предметов» / «Loadout · 12 items» (плюрализация к
  единственному числу не нужна: прежний ключ тоже не склонял «1 предмет»).

Судьба старых ключей:

- `' items · '` (VTKLoc.gd:171) — **остаётся**: использует карточка сета в
  списке (`VTKUI.gd:2387`, «N предметов · M в экипировке»). В новой подписи
  карточки он не участвует.
- `'grid 8 columns'` (VTKLoc.gd:172) — теряет единственного потребителя
  (шапка панели инвентаря, `VTKUI.gd:552`), после удаления счётчика панели
  `keycheck.py` пометит как stale — удалить из `VTKLoc.gd`.

## Стенды

`.check/layout_check.py` пополняется вместе с задачей:

- `PRESENT`: `_make_control_column` (вновь введён), `_make_inventory_panel`,
  `_make_equip_preview`, `_build_set_preview`, `_refresh_preview` уже есть —
  дополнить вызов `Loc.txt("Controls")` в теле `_refresh_preview`.
- `GONE`: строка подводных кнопок превью исчезает — маркер возврата:
  `actions.add_child(apply_btn)`/`qk_btn.pressed.connect` из `_refresh_preview`
  переехали в `_make_control_column`, в `_refresh_preview` их быть не должно;
  новая колонка отделена от сетки.
- `FUNCS`:
  - `("_build_set_preview", [ ... ])` переписывается под каркас трёх колонок:
    три панели + колонка управления + `SIZE_EXPAND_FILL`, параметр `controls`.
  - Запись `("_make_inventory_wall", ["INVEN_ROWS", "Control.SIZE_SHRINK_BEGIN"])`
    не меняем.
  - Запись `("_make_item_cell", [... "Spawn into inventory" ...])` не трогаем
    (шаг 2).
- `HOOKS_GONE` не меняется.

  парсинг всех `.gd` + headless-тесты.

  Управления работают (Применить/Изменить/клавиша/Удалить); в Done
  Сохранить/Отмена; хоткей виден один раз; подпись «Раскладка · N предметов»

  значение уточняем на этапе сборки).
