# Road To Loot — статы аффиксов внутри ванильного списка (спека)

Дата: 2026-10-27 · Мод: Road To Loot (`RTL`) · База: рабочее дерево 0.3.0
Заменяет §11.1 и таблицу маппинга §11.2 спеки 0.3.0 в части того, **куда** пишется аффикс, и
убирает аффикс `condition` из пула (§6 спеки 0.3.0). Остальное из
`2026-10-26-road-to-loot-affixes-live-design.md` (сайдкар, аппликаторы) не трогаем.

## 1. Намерение

Сейчас аффиксы висят отдельным блоком: свой `VBoxContainer` с заголовком
`Passive - <Tier>` и строками дефолтным шрифтом 16. Игрок видит две разные типографики в одном
тултипе, а заголовок дублирует то, что уже говорит цвет.

Хотим: аффиксы читаются как **свои статы предмета** — тем же шрифтом, тем же кеглем, в том же
списке, без заголовка. Тир передаётся цветом значения.

## 2. Цели

- Заголовка `Passive - <Tier>` нет.
- Отдельного блока нет: ни один узел мода больше не является контейнером со своими строками,
  всё живёт в ванильном `Tooltip/Panel/Margin/Elements`.
- Аффикс, у которого есть ванильный аналог, **сливается** с ним суммой и красится цветом тира.
- Остальные аффиксы — строки, неотличимые по виду от ванильных.
- Тумблер `show_affix_block` продолжает работать (выключен — ни одной строки мода).

## 3. Не-цели

- Применение аффиксов к игре — отдельная задача (следующий проход).
- Рамка ячейки, редкость, палитра — без изменений.
- Правка сцен игры, оверрайды скриптов — нет.
- **`condition` как аффикс снят совсем** (см. D2): задумка была поднять износ выше 100%
  («условные 120»), показать это внутри ванильной строки `Condition` нельзя — там текущий
  износ с цветом по порогу. Вернёмся отдельной задачей, когда будет решение по механике.

## 4. Факты, добытые дампом (снимают «неизвестно» из §11.2)

Дамп `res://UI/Interface.tscn` (живой узел `Tooltip`; `UI/Elements/Tooltip.tscn` — мёртвая сцена,
её структура не совпадает с `Tooltip.gd`):

| факт | значение |
|---|---|
| контейнер статов | `Tooltip/Panel/Margin/Elements` — `VBoxContainer` |
| строка стата | `Label` (не `HBoxContainer`), текст = подпись вместе с двоеточием (`"Capacity:"`) |
| значение | единственный ребёнок строки, `Label name=Value`, лежит по `offset_left` = ширина текста подписи + 2…3 px, ширина бокса 40…52 |
| `Rarity` | ребёнок строки `Type`, прижат к правому краю (`anchors 1,1`, `offset_left = -256`, `h_align = right`) |
| шрифт | `res://UI/Themes/Theme.tres`, `Lora-Regular`, `Label/font_size` по умолчанию 16, у каждой строки стата override 12; цвет `(1,1,1,1)` |
| порядок строк | `Title, Type, Separator, Info, Equipment, Condition, Weight, Value, Caliber, Damage, Penetration, Protection, Capacity, Insulation, Health, Energy, Hydration, Mental, Temperature, Nested, Cures, Subpanel` |
| частота `Update()` | каждые 10 физических кадров, пока курсор над предметом (`Interface.gd:351`) |
| `Reset()` | скрывает **фиксированный** список строк, про строки мода не знает |

Проверено headless: ширина подписи = `font.get_string_size(text, LEFT, -1, 12).x`, запечённые
сдвиги ванили равны ей +2…3 (`Capacity:` 53 → 55, `Weight:` 44 → 47, `Insulation:` 62 → 62).
Поэтому клон строки с новым текстом получает корректный сдвиг значения без layout-прохода.

## 5. Подход

**A (выбран).** Переписываем значение существующих строк + добавляем клоны ванильной строки.
Отвергнуты: свой блок, стилизованный под ваниль (не даёт суммы без перезаписи ванильной цифры);
полная пересборка списка статов (повторять всю ванильную логику и драться с другими модами).

## 6. Решения

| # | Решение |
|---|---|
| D1 | Слияние суммой в существующую строку: `damage`, `carry`, `insulation`, `protection` |
| D2 | `condition` удаляется из `RTLPool` (обе категории) и из отображения: новых роллов не даёт, строку `Condition` не трогаем вовсе. Легаси-ролл `condition` из сайдкара 0.2.x в тултипе **не показывается** (стат больше не существует), но пишется одна строка в лог при `debug_enabled` |
| D3 | Всё остальное — новая строка-клон строки `Capacity`, вставленная перед `Nested` (если его нет — в конец `Elements`) в фиксированном порядке списка |
| D4 | Красится только значение, подпись остаётся белой |
| D5 | Цвет — палитра тира из `RTLDisplay._border_color(tier)`, отдельной константы не заводим |
| D6 | Знаки: минус у `stamina_drain`, `thirst_drain`, `hunger_drain`, `sanity_drain`, `noise`, `recoil`; плюс у остальных |
| D7 | Ключ `show_affix_block` не переименовываем (иначе у пользователя сбросится значение), меняем только `name`/`tooltip` в MCM |
| D8 | Вся строковая логика — чистые функции в `RTLText` (`stat_label`, `stat_value`), покрываются `test_rtl_text.gd`; вёрстка в `RTLDisplay` не форматирует числа сама |

### 6.1 Таблица слияния

| stat | строка | формула суммы | текст значения |
|---|---|---|---|
| `damage` | `Damage` | `int(round(base * (1 + x)))` | `120` |
| `carry` | `Capacity` | `int(capacity + x)` | `+15kg` |
| `insulation` | `Insulation` | `int(base + base * x)` | `+30` |
| `protection` | `Protection` | `int(protection + x)` | `Level 2` |

База берётся из `slotData.itemData` каждый вызов; текст из лейбла не читается никогда.

`condition` в таблице нет: он снят из пула (D2), ванильная строка остаётся нетронутой.

### 6.2 Новые строки

Подпись — `RTLText.stat_label(stat)` (алиасы: `low_hp_regen` → `Low HP Regen`,
`low_hp_damage` → `Low HP Damage`, `fire_rate` → `Fire Rate`, `max_hp` → `Max HP`, остальное
`capitalize().replace("_", " ")` + `:`). Значение — `RTLText.stat_value(stat, value, unit)`:

| unit | вид |
|---|---|
| `pct` | `+12%` / `-18%` (знак по D6) |
| `rate` | `+0.03 HP/s` |
| `kg` | `+5kg` |
| `flat` | `+1` |
| `hp` (легаси) | `+25` |
| `mult` (легаси) | `x1.2` |

Порядок новых строк — константой в `RTLPool` (порядок пула), чтобы список не переставлялся
между предметами.

## 7. Идемпотентность

1. `Update()` перезапускается каждые 10 кадров и возвращает ванильные тексты → слияние
   пересчитывается **на каждом** вызове `apply_tooltip`, раннего `return` по `instance_id` для
   слияния нет.
2. Свои строки переживают `Reset()` (он их не знает), поэтому при смене предмета они снимаются:
   `_drop_rows()` + `_sweep_rows(parent)` по мете `rtl_stat`, как уже сделано для блока
   (`_drop_block`/`_sweep_boxes`). Снятие — `remove_child` до `queue_free`, иначе Godot
   переименует замену в `_rtl_stat2` в том же кадре.
3. Свои строки перестраиваются только при смене предмета; в остальные вызовы обновляется лишь
   текст и цвет (без churn'а layout'а).
4. `clear_tooltip()` (хук `tooltip-info-post`) снимает и строки: `Reset()` их не скрывает, иначе
   они повиснут над инфо-панелью.
5. Если строка-цель не найдена (предмет не имеет этой базы, легаси-ролл) — аффикс уходит в
   новую строку с той же подписью, а не теряется. Исключение — `condition` (D2): он не
   показывается вовсе.

## 8. Проверка

Headless: `test_rtl_text.gd` — `stat_label`/`stat_value` по всем статам пула + легаси-единицы;
`test_rtl_pool.gd` — `condition` больше не выпадает, `ACTIVE_RELEASE == 2`, 15 записей.
UI headless не проверяется; ручной чек-лист (дополняет §15.1 спеки 0.3.0):

1. Оружие с тиром: `Damage` показывает сумму, цифра цветом тира, `Recoil`/`Fire Rate` — новые строки тем же шрифтом.
2. Одежда с тиром: `Capacity` — сумма `+Nkg`, `Insulation` — сумма, «дренажи» — новые строки.
3. Заголовка `Passive - …` нет ни на одном предмете.
4. `Condition` в тултипе выглядит и красится как без мода.
4. Тултип открыт 10+ секунд: строки не размножаются, значения не плывут.
5. Навести на второй предмет: чужих строк и чужих цифр нет.
6. Инфо-панель (без предмета) — строк мода нет.
7. `show_affix_block = false` — строк мода нет, ванильный тултип байт-в-байт как без мода.

## 9. Что остаётся строителю

- Точный запас по ширине панели (256) для длинных подписей вроде `Stamina Drain:` — проверить
  на самом длинном стате в игре и, если не влезает, сокращать подпись, а не кегль.
- Оставлять ли `RTLRoll.format_affix`/`format_delta` (сейчас не вызываются) — можно удалить.
- После снятия `condition` единственный потребитель гейта `needs: "damage"` в
  `RTLRoll.build_affixes` исчез (ветка остаётся мёртвой). Либо удалить ветку и `needs` из всех
  записей, либо оставить под будущие статы — решить в задаче, не молча.
- Нужен ли дамп структуры из плана T3.2 как постоянный debug-лог (он больше не нужен: структура
  снята, но при апдейте игры может поехать — предлагаю оставить вызов под `debug_enabled`).
