# ThermalVTK 2.1.0 — чистка кадра, независимый X-ray, видимость ромба

Дата: 2026-10-25
Статус: одобрено пользователем (вариант B, версия 2.1.0, Distance режет и трупы)
Основание: разбор сессии (перечень горячих точек) + решения пользователя:
вариант B (один сбор → один проход применения), версия 2.1.0, ромб — рейкаст.
Отменяет: пункт «ромб не читается сквозь стены» из 1.11.5 (шейдер
`VTKNomadMarker.gdshader:2`, `depth_test_disabled`).

## В чём проблема

1. Кадр ESP аллоцирует на каждого NPC: четыре прохода `_entries.keys()`,
   свежий Dictionary опций на запись на кадр (`_opts_for`), Dictionary
   кандидата на запись, `duplicate()` + `sort_custom` с новым лямбда-Callable
   в `Tracker.pick_nearest`, `c["id"] not in keep` (линейный поиск).
2. X-ray заперт над ESP: `ThermalVTK._apply_mode` выключает ESP целиком при
   `outline_enabled = false`, поэтому `_draw` не зовётся и окон триггеров нет.
   «X-ray без ESP» не работает.
3. Ромб номада рисуется сквозь стены: шейдер без depth-теста (цена фикса 1.11.5
   для прицела) и без проверки дистанции.
4. Хуки продолжают работать при выключенном слое: каждый шаг каждого NPC
   регистрирует запись (`variant`, аллокация) и строит строку лога.
5. NVG: `_apply_uniforms` (18 параметров + материал мины) безусловно раз в
   0.1 с; `_retry_mines` пересобирает меши мины без лимита попыток; при
   выключенном тепловизоре `_off_frame_upkeep` аллоцирует `keys()` каждый кадр.
6. Мелочь: мёртвые `_labels_state` и (после рефакторинга станет живым)
   `e["dist"]`, двойной `_read_state` в `_on_ai_changestate`, устаревшие
   комментарии про depth-тест ромба.

## Решения

- **Три слоя, один сбор.** Контур (`outline_enabled`), x-ray (`outline_xray`),
  ромб (часть контура). ESP-узел активен, если активен хотя бы один слой;
  внутри кадра каждый слой решает, что рисовать.
- **CAP принадлежит контуру.** X-ray-окна CAP не занимают: их мало, они
  временные и ограничены дистанцией события. Сейчас окно конкурирует за CAP
  с обычными кольцами.
- **Ромб — рейкаст.** Раз в `LOS_EVERY` кадров (со сдвигом по `id`), результат
  кэшируется в записи. Живое окно x-ray в пределах дистанции события снимает
  проверку стены; иначе стена прячет ромб и в обычном виде, и в прицеле.
  Шейдер ромба не трогаем (глубина не включается — регресс 1.11.5).
- **Мёртвые под Distance.** `Distance` распространяется и на трупы: тултип
  обещает «outlines are hidden past this range», теперь это правда и для
  остывающих тел. Изменение поведения, отсюда строка в CHANGELOG.
- **Фоновые хуки.** Припаркованный слой больше не регистрирует незнакомых ботов
  из триггер-хуков; теги окон для уже известных записей остаются (их читают
  debug-надписи), `ai-death-post`/`ai-deactivate` остаются нетронутыми (иначе
  вернётся баг «труп снова свежий после переодевания шлема»).
- **Версия** 2.1.0 (minor: x-ray без ESP — новое поведение, ключи конфига и
  данные сохранений не меняются).

## Предлагаемый дизайн

### VTKESP: кадр

`_process`:

1. Парковка, если ни один слой не активен (`enabled`, `xray_layer`,
   `marker_visible` — все false). В парковке: раз в 120 кадров прун мёртвых
   записей (сейчас `_entries` копятся всю сессию).
2. `_weapon.tick()`, scope/pip, `_outline.set_scoped`,
   `_weapon.set_scope_mode(scoped and any_layer, pip)` — **при любом активном
   слое**, не только при контуре. Причина: патч оружия двигает материалы
   ствола в прозрачный проход с приоритетом выше кольца. Без него x-ray-кольцо
   без контура красится поверх корпуса и прицела. Mask-режим прицела тоже
   общий: он про кольца в линзе, а не про то, какой слой их зажёг.
3. `_frame += 1`, дренаж `_pending` (см. ниже).
4. Игрок из кэша (`_player()`), позиция; нет игрока — только `_dbg_tick`.
5. `_draw(ppos)` — сбор + применение колец (контур и/или xray).
6. `_labels_sync()` (только при `Dbg.enabled`), `_markers_sync()`, `_dbg_tick`.

`_draw(ppos)` (сохраняет сигнатуру: её зовут тесты):

1. **Сбор**, один снапшот `_ids_frame := _entries.keys()`:
   - невалидная/вне дерева запись → `_outline.clear(id)`, `erase`;
   - `dead` синхронизируется с узлом (`Tracker.mark_dead`);
   - `dist` считается один раз и кладётся в запись;
   - `win := Tracker.pick_trig(e, now)` — один раз на запись на кадр, кладётся
     в запись (сейчас `pick_trig` зовётся дважды: `_draw` и `_label_text`);
   - `Tracker.apply_state` по `_frame % POLL_EVERY`, как теперь.
2. **Кандидаты контура**: записи с валидным узлом и `dist <= p_dist`. Трупы
   остаются кандидатами (их кольцо и есть `cool`-фейд) и делят CAP с живыми —
   как сейчас. Записи кандидатов переиспользуются из пула (`_cand_pool`), а не
   создаются; `pick_nearest` сохраняет сигнатуру и тест, но получает пул.
   `keep` — переиспользуемый Dictionary вместо `in` по массиву.
3. **X-ray набор**: `xray_layer and p_trig`, не `dead`, `dist <= win.dist`.
4. **Применение**: объединение «контур ∪ xray» (`_want`, переиспользуемый
   Dictionary; xray побеждает). Опции — переиспользуемый Dictionary в записи
   (`e["opts"]`), поля перезаписываются на месте (`cat`, `state_key`, `cool`,
   `rim`, `brightness`, `grow`, `xray`). `_opts_for` остаётся как «форма» и для
   тестов, вызывается один раз на запись. `_outline.apply/refresh` как сейчас;
   записи вне `_want` → `_outline.clear(id)` (новый `VTKOutline.clear_not_in`).
5. Счётчики для `_dbg_tick` + `Time.get_ticks_usec()` вокруг шага 1–4, только
   при `Dbg.enabled` (постоянный дешёвый замер, не временный код).

Публичный API слоёв: `set_layers(contour: bool, xray: bool)` вместо
`set_enabled`; `marker_visible` выставляется им же (`= contour`), поле остаётся
публичным для тестов. `ThermalVTK._apply_mode` зовёт `set_layers(on and
_outline_enabled, on and _xray_enabled)`, где `on = thermal and nvg`; отдельный
`_xray_enabled` из `rec.outline_xray`.

Слой xray без контура: кольцо рисуется только на время окна, шейдер сразу
x-ray (`near_only`, `carve`), между окнами `clear`. Тот же путь, что уже
работает для окна при включённом контуре.

### VTKESP: ромб

`_markers_sync` идёт по `_ids_frame` (один снапшот на кадр), для номадов:

- живость/дерево/`dead` — как сейчас;
- `win` и `dist` из записи (если сбора не было — считает сам, тесты);
- `xray_live = p_trig and непустой win and dist <= win.dist` → видно всегда;
- иначе раз в `LOS_EVERY` кадров (сдвиг по `id`) рейкаст из камеры в
  `mi.global_position`; результат в `e["los"]`, между проверками читается;
- `mi.visible = los`.

Рейкаст: переиспользуемый `PhysicsRayQueryParameters3D`, `collide_with_areas =
false`, `hit_from_inside = false` (камера внутри капсулы игрока не мешает).

Исключения из запроса (иначе ромб всегда скрыт):

- **Игрок целиком.** Собираем `CollisionObject3D` в поддереве узла из группы
  `Player` (тело, капсула, оружие в руках) и кладём их RID в `exclude`. Луч
  стартует из камеры, которая обычно внутри капсулы игрока; без исключения
  `hit_from_inside = false` не спасает — капсула пересекается по пути.
- **Сам номад.** Все `CollisionObject3D` в поддереве узла-номада в `exclude`:
  луч, идущий в точку над головой, иначе задевает его же капсулу у основания и
  ромб пропадает вплотную.
- **Блокирует любой `PhysicsBody3D`** (StaticBody3D, RigidBody3D,
  CharacterBody3D) вне этих двух поддеревьев. `Area3D` не блокируют
  (`collide_with_areas = false`). Список `exclude` пересобирается при каждом
  рейкасте (номад может умереть/пересобрать капсулу), это единицы RID на
  `LOS_EVERY` кадров.
- Нет камеры, `World3D` или физического пространства (headless, меню) →
  «видно», чтобы тесты и меню не падали.

Открытый риск: прозрачная геометрия с коллизией (стекло, сетка забора) и
другой NPC на линии спрячут ромб. Для ромба это скорее верно (тело реально
закрывает), но стекло — нет. Проверяется в игре пунктами 9–10 ручного списка;
если стекло мешает, второй итерацией добавляем в `exclude` коллайдеры с
материалом прозрачности (по `collision_layer`, если слой опознан) — это
отдельная правка, в текущий скоуп не входит.

Дистанция ромба не меняется.

### VTKESP: хуки и регистрация

- `_trig_event`: не регистрировать незнакомого бота, если ни один слой не
  активен (ранний выход до `_register`); тег известной записи остаётся.
- `if Dbg.enabled:` на горячих строках (`_trig_event` ×2, `_to_trail` в
  weapon — см. ниже); холодные (регистрация хуков, старт) не трогаем.
- `_on_ai_changestate`: `_read_state` один раз в локальную.

### Страховка от лишних `%` и мелких аллокаций

- `VTKTracker.EMPTY_WINDOW` (`const {}`, read-only) вместо `return {}`:
  `pick_trig` сейчас аллоцирует пустой Dictionary на каждую запись на кадр.
- `_dbg_tick(delta, has_player: bool, ppos: Vector3)` собирает строку внутри,
  после проверки `_dbg_cd` (сейчас строка собирается каждый кадр).
- `VTKWeaponOcclusion._patch_mesh`: строительство `trail` под `Dbg.enabled`.
  Это не горячий путь (мета `VTK_OCC` отсекает повторные заходы), правка — для
  консистентности, в выигрыш не записываем.

### VTKNVG

- `_dirty` вместо безусловного `_apply_uniforms` раз в 0.1 с. Помечают:
  `apply_config`, `set_thermal_enabled`, `set_palette_mode`, `set_state_colors`,
  `_reset_daylight`, смена `worn` в `_process`, изменение `_snow_trim` в
  `_daylight_tick`. Пуш — на тике `TICK`, чтобы пачка сеттеров схлопнулась.
  `_try_install_shader` продолжает пушить сразу (десинк старта не возвращаем).
- `_player_pos()` только внутри `if on`.
- `_off_frame_upkeep`: ранний выход при пустом `_mines`.
- `_retry_mines`: счётчик попыток в `_mine_watch`, после 50 тиков (5 с) запись
  выкидывается с одним `warn_once` (сейчас мина без визуала пересобирается
  вечно).
- `_drain_pending`: кэш вердикта по `script.get_instance_id()`
  (`0` — мимо, `1` — NVG, `2` — Mine), `resource_path` строится один раз на
  скрипт, а не на узел. То же для `_scan_node` (общий хелпер).

`_environment()` не кэширую: выигрыш — два `Object.get` на кадр, а риск
устаревшего Environment после подмены ресурса внутри карты ненулевой.

### Тесты (`.check`, существующие + новые)

- `test_esp`: `set_enabled` → `set_layers`; новые: окно x-ray при
  `xray_layer = true` и контуре off даёт кольцо, по истечении — `clear`;
  окно не вытесняется CAP; `_label_text` читает `win` из записи; ромб не
  виден при «стене» и виден при живом окне (фейковый рейкаст через
  подменяемый метод `_los_raycast`); парковка не регистрирует незнакомого бота.
- `test_outline`: `clear_not_in` чистит только отсутствующих.
- `test_tracker`: `EMPTY_WINDOW` (тот же объект в двух вызовах, read-only),
  `pick_nearest` не портит входной пул по контракту (мутирует только копию).
- `test_profile`: FakeESP получает `set_layers`; `_apply_mode` передаёт оба
  флага.
- `test_settings`: `_xray_enabled` из `rec.outline_xray`.
- Прогон: `powershell -NoProfile -ExecutionPolicy Bypass -File .check\check.ps1`
  — зелёный по трём признакам (нет `SCRIPT ERROR`/`Parse Error`/`Invalid
  call`, есть `tests passed`, код 0).

### Ручная проверка в игре

1. Стена между игроком и номадом → ромба нет; вышел из-за угла → есть.
2. Прицел, стена между → ромба нет; чистая линия → есть.
3. Номад стреляет за стеной, X-ray on → ромб виден сквозь стену на время окна.
4. То же, X-ray off → не виден.
5. ESP off + X-ray on: стрелявший в окне получает кольцо сквозь стену, между
   окнами колец нет.
6. ESP on + X-ray off: обычные кольца, вспышек сквозь стены нет.
7. `Distance` режет живые кольца и (новое) трупы.
8. Диагностический лог: строка раз в секунду содержит время кадра ESP; до/после
   чистки сравнить в бою.
9. ESP off + X-ray on, стрельба в прицеле: кольцо видно сквозь стену, но не
   красит корпус прицела и линзу (проверка патча оружия при `xray_layer`).
10. Ромб за стеклом и за сеткой забора: если прозрачное укрытие прячет ромб
    там, где видно тело, фиксируем как известное ограничение (см. риск выше).

## Вне скоупа

- Кэш `Environment`, полный отказ от `keys()`-снапшотов, переписывание
  `_reseed` (фриз на надевании шлема), общий `node_added`-диспетчер для
  VTKESP/VTKNVG.
- Дистанция ромба, поведение `cool`-фейда трупов, CAP больше 24.
- Включение/выключение ромба отдельным тумблером.
