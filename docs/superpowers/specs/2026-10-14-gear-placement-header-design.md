# Вкладка «Снаряжение» кладёт в снаряжение + сдвиг шапки

Дата: 2026-10-14
Целевая версия: 4.17.1 (поведение + мелкая правка UI; 4.17.0 уже выпущен → патч)

## Проблема

**A. Клик по предмету на вкладке «Снаряжение» экипирует его.**
Шаг 2 (каталог) рисует клетки `_make_item_cell(res, "", true)` (`VTKUI.gd:1504`) — целевой слот
пустой. Клик зовёт `_place_into(it, "")` (`VTKUI.gd:2738` → `:2769`), а `_place_into` при пустом
слоте падает в `Draft.add` (`VTKUI.gd:2804`), который **первым делом** зовёт `free_slot_of(slots)`
(`VTKDraft.gd:49`) и заполняет свободный слот экипировки. Граната (`slots = Grenade_1/Grenade_2`),
оружие, броня поэтому уезжают в снаряжение вместо рюкзака. Спека дизайна
(`2026-10-05-loadouts-item-picker-design.md:241`) прямо говорит: клик на шаге 2 идёт в снаряжение.
Авто-экип задуман только для шага 1 (каталог «Все предметы» с целью → `add_to_slot`; чип без цели).

**B. Шапка «V VOSTOK TOOLKIT» перекрывается HUD-элементами.**
Верхний рейл панели стоит на `offset_top = 24` (`VTKUI.gd:455`). Счётчик убийств — отдельный
CanvasLayer поверх панели, его `Label` прибит в `(10,10)` шрифтом 13 (`VTKKillCounter.gd:26`; в
убежище показывает `"Shelter"`, `:204`). Низ текста доходит примерно до y≈28, рейл начинается в 24 —
буквы счётчика/Shelter и заголовок слегка наезжают друг на друга (запас, заложенный в комментарии
`VTKUI.gd:448`, оказался мал).

## Цели

1. Клик по любой клетке шага 2 («Снаряжение») кладёт предмет в **снаряжение** (рюкзак), без
   заполнения слотов экипировки. Стекирование и обоймы (`count`) работают как раньше.
2. Шаг 1 не меняется: явная цель → вытеснение слота (`add_to_slot`), чип «Все предметы» → авто-экип.
3. Верхний блок панели (рейл, полоса, вкладки, область содержимого) сдвигается вниз, чтобы заголовок
   выходил из-под счётчика/Shelter.

## Не-цели

- Не переносим сам счётчик убийств и не трогаем его позицию/логику.
- Не трогаем `_place_into` для шага 1 и `_target_slot`.
- Не рефакторим `Draft.add` сверх вынесения общей ветки в приватный хелпер.

## Дизайн

### A. `VTKDraft.gd` — новая чистая `add_gear`

```gdscript
func add_gear(path: String, item_name: String, amount: float, type_name: String, counted: bool = false) -> void
```

Кладёт предмет в `gear`, **минуя** `free_slot_of`. Логика совпадает с gear-веткой `add`
(`VTKDraft.gd:53-65`):

- если путь уже в `gear` (`gear_index_of`): `count` (обоймы) или `amount` инкрементируется, новых
  записей не появляется;
- иначе append дескриптора `_desc(...)`; при `counted` проставляются `count = 1`, `amount = 0.0`,
  `full_mag = true`.

Общую ветку вынести в приватный хелпер `_gear_add(path, item_name, amt, type_name, counted) -> void`
и звать его из обеих функций: `add` — как фолбэк после `free_slot_of` (`:53`), `add_gear` — сразу.
Так правило стекирования живёт в одном месте. Функция чистая (ни `load()`, ни путей внутрь игры) и
покрывается headless-тестом.

### A. `VTKUI.gd` — проброс `force_gear`

- `_make_item_cell(item, forced_slot = null, gear := false, force_gear := false)` — новый параметр.
- В обработчике клика (`:2738-2741`) звать `_place_into(it, slot, force_gear)`.
- Шаг 2 (`:1504`): `_make_item_cell(res, "", true, true)`.

```gdscript
func _place_into(item, slot: String, force_gear := false) -> void
```

В начале (после извлечения `path`/`t`/`amt`/`counted`/`slots`/`item_name`): если `force_gear` —
`_draft.add_gear(path, item_name, amt, t, counted); _after_place(); return`. Иначе — прежний путь
(`slot != ""` → `add_to_slot`, иначе `add`).

`_make_item_cell` зовётся только из двух мест: полка шага 1 (`:2364`, без новых аргументов) и сетка
шага 2 (`:1504`, `force_gear = true`). Прочие вызовы отсутствуют.

### B. `VTKUI.gd` — сдвиг верхнего блока

Сдвинуть вниз на 10px (величина уточняется по месту после проверки в игре):

| Узел | Было | Стало |
|---|---|---|
| рейл `offset_top` / `offset_bottom` | 24 / 54 | 34 / 64 |
| полоса `rail_sep` top / bottom | 56 / 57 | 66 / 67 |
| `tab_bar` top / bottom | 58 / 88 | 68 / 98 |
| `_scroll` top | 92 | 102 |

`_scroll.offset_bottom = -4` и все `offset_left/right` не трогаем. Комментарий `VTKUI.gd:445-451`
обновить под новое значение (объясняет, почему верх не 0).

## Тестирование

- Headless (`test_draft.gd`):
  - `add_gear` на предмете со слотами (`["Grenade_1","Grenade_2"]`) → запись в `gear`, `equip`
    остаётся пустым (регрессия бага).
  - повторный `add_gear` того же пути → одна запись, `amount` (или `count` при `counted=true`) растёт.
  - `counted=true` → `count = 1`, `amount = 0.0`, `full_mag = true`.
  - `add` (старый) по-прежнему заполняет `equip` первым — поведение шага 1 не сломано.
- Стенды `layout_check.py` и `check.ps1` — списки без изменений, зелёные.
- Ручная проверка в игре:
  - На вкладке «Снаряжение» граната (и оружие, броня) уходит в рюкзак, а не в слоты снаряжения.
  - На шаге 1 явная цель по-прежнему вытесняет выбранный слот.
  - Заголовок «V VOSTOK TOOLKIT» не перекрывается счётчиком и надписью «Shelter».

## Риски

- **Двойное добавление**: если предмет уже стоит в экипировке, `add_gear` добавит его ещё и в рюкзак.
  Поведение совпадает с прежним фолбэком `add` (тот тоже не проверял equip); вне рамок этой правки.
- **Постоянная величина сдвига**: 10px подобрано арифметикой по высоте шрифта; HUD-шрифт игры может
  быть крупнее. Проверяется глазами, при необходимости правится значением.
