# Вкладка сетов: слоты и Apply

Дата: 2026-10-04
Версия: 4.2.0 (minor — формат сохранённых данных не меняется)
Статус: утверждён

## Контекст

Макет `docs/mockups/sets-tab-variant-a-v3.html` описывает целевую вкладку сетов целиком:
карточки сохранённых сетов, слоты, два поиска, мультивыбор типов, захват любой клавиши,
Shift-семантика. Реализуем это по частям, чтобы каждую часть можно было проверить в игре.

Данные и движок применения уже готовы и проверены пользователем в 4.0.0:
формат `equip`/`gear`, аддитивное применение, отказ от `Grid.ClearGrid()` и `interface.Reset()`,
`_pack_own()`. Ничего из этого не переписывается.

Сейчас редактор плоский: поле имени, чипы типов с одиночным выбором, сетка предметов,
список содержимого, `Save`/`Clear`. Слотов в UI нет вообще — слот выводится в момент
сохранения, неявно.

## Границы слайса

Входит:

- подпись назначения предмета в ячейке сетки;
- явная привязка предмета к слоту при клике;
- две секции в редакторе: «Экипировка» и «Снаряжение»;
- карточки сохранённых сетов с кнопкой «Применить»;
- удаление кнопки `Inventory`.

Не входит (следующий слайс):

- захват любой клавиши вместо циклов 7/8/9;
- Shift-семантика «только инвентарь» по хоткею;
- поиск предметов;
- мультивыбор чипов типов;
- метка «Синхронизировать» из макета.

## Формат данных

Не меняется. `loadouts.json` хранит:

```
equip: { "<SlotName>": { path, amount, chamber, attachments } }
gear:  [ { path, amount } ]
```

Точки входа применения уже существуют и не меняются:

- `VTKData.load_loadout(name)` → `apply_loadout(name, true)` — надеть и положить остальное;
- `VTKData.spawn_loadout(name)` → `apply_loadout(name, false)` — только инвентарь.

Кнопка «Применить» вызывает `VTKData.load_loadout(name)`.

## Назначение предмета

Источник истины — сам предмет. Угадывать по категории нельзя: макет это запрещает явно.

- у предмета есть `slots` → он попадает в экипировку;
- нет `slots` → он попадает в снаряжение.

### Несколько подходящих слотов

Берём **первый по порядку**, какой вернул `slots`.

В ячейке сетки показываем **все варианты через запятую**, чтобы неявный выбор был виден
пользователю. Пример подписи: `Primary, Secondary`.

При сохранении в `equip` попадает только выбранный (первый) слот.

**Известное ограничение.** Выбрать слот вручную нельзя: если предмет подходит в несколько
слотов, всегда побеждает первый. Это осознанно принято на этом слайсе — ручной выбор слота
требует другого элемента управления и отдельного обсуждения. Пока пользователь видит все
варианты в подписи и может убрать предмет кнопкой `✕`.

### Ячейка сетки

Под именем предмета — строка назначения: имя слота либо «снаряжение».

Состояния:

| Состояние | Вид |
|---|---|
| Свободен | обычная рамка, подпись назначения |
| Уже в сете | золотая рамка; счётчик `×N` только для снаряжения |

Для предмета в экипировке счётчик не показывается: там ровно один предмет на слот, так что
считать нечего.

## Клик по предмету

- **Есть `slots`** → `equip[slot] = descriptor`. Второй клик по другому предмету для того же
  слота **молча заменяет** первый, без предупреждения (макет, строка 311).
- **Нет `slots`** → добавляется в `gear`. Повторный клик даёт `amount + 1`.

## Редактор

Две секции.

**Экипировка** — строки только по заполненным слотам:
`слот | название | количество | ✕`

**Снаряжение** — строки:
`точка | название | − N + | ✕`

`✕` убирает только из своей коллекции. Степпер количества меняет `amount` в `gear`.

## Карточки сохранённых сетов

Вместо плоского списка:

- имя;
- мета-строка `N предметов · M в экипировке`, где M — число ключей в `equip`;
- капс быстрой клавиши: цифра, `?` если не назначено, клик циклит 7/8/9 как сейчас;
- чипы слотов с хвостом `+K`, если слотов больше, чем помещается;
- подвал: `Применить` | `Изменить` | `✕`;
- карточка-создатель `+ Создать сет`.

Кнопка `Inventory` с карточки убрана.

## Ограничения реализации

1. **`OptionButton` в этой игре не использовать.** В 4.1.2 его попап показывал один пункт
   вместо двух при корректных данных. Для выбора с чего угодно — кнопки.
2. **Локализация.** Каждая новая строка UI — новая запись в `RU` в `VTKLoc.gd` того же прохода.
   Функция `Loc.txt()`, не `tr()`. Строки с кавычками — в одинарных кавычках.
3. **Кодировка.** Файлы UTF-8. PowerShell-консоль кириллицу искажает — проверять байтами или
   UTF-8 отчётом.
4. **Отступы — только табы.**
5. **`mod.txt`** — одна строка, без BOM и переводов строк.
6. Не вызывать `Grid.ClearGrid()` и `interface.Reset()` ни в этом слайсе, ни дальше.

## Проверка

Статическая: `.check/check.ps1` — 7 скриптов должны пройти `godot --check-only`.

Динамическая — в игре, руками:

1. предмет с одним слотом показывает имя слота, попадает в «Экипировку»;
2. предмет без слотов показывает «снаряжение», попадает в «Снаряжение»;
3. предмет с несколькими слотами показывает их через запятую, кладётся в первый;
4. второй предмет в тот же слот заменяет первый;
5. `✕` в «Экипировке» не трогает «Снаряжение» и наоборот;
6. «Применить» надевает экипировку и раскладывает остальное в инвентарь;
7. после «Применить» чужие предметы в инвентаре остались на месте;
8. карточка показывает верное `N предметов · M в экипировке`;
9. перезапуск игры — предметы из применённого сета на месте.
