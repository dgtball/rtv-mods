# ThermalVTK 1.10.0 — переделка X-ray Triggers

Дата: 2026-10-22
Статус: одобрено пользователем (семантика, фикс прицела — вариант A, имя настройки остаётся, версия 1.10.0)
Отменяет: «аддитивные триггеры» из 1.9.0 (удаление `trigger_mode`) и глобальный свап ринга через `set_xray` из 1.9.1/1.9.3.

## В чём проблема

Один тумблер MCM `outline_xray` («X-ray Triggers») сейчас заперт над тремя не связанными по смыслу вещами:

1. шейдер кольца навсегда без depth-теста (сквозь стены, всегда);
2. события-триггеры (выстрел, крик, шаги, перезарядка, крик боли, граната) тегируют окна раскрытия на ботах;
3. суффикс с отсчётом `[fire 3.4s 100m]` в отладочных надписях над NPC существует только пока тумблер включён.

Из этой путаницы идут два видимых бага:

- При выключенном тумблере кольцо прячется за стекло прицела: в оптике ринга не видно (`VTKOutlineRing.gdshader:8-10` — там задокументирована причина: стекло прицела пишет глубину в пару сантиметров от глаза и z-отсекает всё за ним; окклюдед-вариант держит depth-тест).
- Смысл тумблера расходится с названием: «X-ray» на деле контролирует в основном, живут ли окна триггеров вообще.

## Решения (одобрены пользователем)

- **Триггер-система живёт всегда** (независимо от тумблера): события тегируют окна, отладочные надписи с отсчётом показываются при включённом debug log — по аналогии с надписями состояний. Визуально надпись есть, даже если X-ray выключен.
- **Тумблер OFF** = кольцо никогда не светит сквозь стену. Ринг всегда окклюдед (стены/Distance прячут, оптика показывает), окна триггеров тегируются и видны только в надписях.
- **Тумблер ON** = по событию в диапазоне кольцо этого бота на время окна свапается на x-ray-шейдер (сквозь стены и стекло прицела) с готовым cool-фейдом. Между окнами ринг обычный.
- **Ринг сквозь стекло прицела виден всегда** в обоих режимах — главное условие, включён тепловизор (ESP). От тумблера X-ray видимость ринга в оптике не зависит.
- **Дистанция раскрытия** остаётся по каждому событию (`trigger_*_dist`) и может превышать ESP Distance — как в аддитивной реализации 1.9.0.
- **Фикс стекла прицела** = на стороне шейдера. Окклюдед-шейдер сравнивает глубину вручную и считает любого окклюдера ближе порога (~0.2–0.3 м — там живёт только линза прицела и предметы, вдавленные в камеру) «не окклюзией». Стены спрятывают кольцо как раньше.
- **Имя настройки** остаётся «X-ray Triggers»; переписывается только тултип под семантику событий. Ключ `outline_xray` и сохранённые значения не переезжают (без сброса настроек).
- **Надписи** остаются привязанными к debug log ровно как надписи состояний: при включённом логе показываются всегда, тумблер X-ray на них не влияет. Суффикс триггера появляется при активном окне.
- **Версия** = 1.10.0 (minor; ключи и данные сохранений совместимы).

## Предлагаемый дизайн

### Таблица семантики OFF/ON

| Составляющая | OFF | ON |
|---|---|---|
| Шейдер ринга, в покое | окклюдед (ручное depth-сравнение) | окклюдед (ручное depth-сравнение) |
| Шейдер ринга, активное окно | окклюдед — кольцо на вспышку не реагирует | x-ray (`VTKOutlineRing.gdshader`), свап по каждому боту отдельно |
| Затухание ринга внутри окна | нет | `cool` идёт 0→1 по ходу окна (уже готовая математика) |
| Теги триггеров (триггер-система) | работают всегда | работают всегда |
| Суффикс отсчёта в надписи | при активном окне, при включённом debug log | при активном окне, при включённом debug log |
| Ринг сквозь стекло прицела | да (по ручному depth-сравнению) | да (в окне и через x-ray-шейдер) |
| Раскрытие дальше Distance | н/д | да, ограничено дистанцией события |

Предусловие для любого ринга: включён тепловизор (ESP включен).

### Изменения в конвейере ринга

- `VTKOutline.gd`
  - `apply()` строит материал ринга всегда из `Shaders.ring(false)` (окклюдед); глобальное поле `_xray` и `set_xray()` удаляются.
  - Новый `set_entry_xray(id: int, on: bool)`: меняет шейдер только у ринга этого бота между окклюдед и x-ray, без повторов при одинаковых вызовах.
  - `refresh()` продолжает читать `cool` из opts (фейд окна — прежний путь).
- `VTKOutlineRingOccluded.gdshader`
  - становится `depth_test_disabled` и сравнивает глубину сам: сэмплирует `DEPTH_TEXTURE` по `SCREEN_UV`, линеаризует и ставит `ALPHA = 0` там, где геометрия в буфере ближе фрагмента — кроме случая, когда окклюдер внутри полосы отсечения ближней плоскости (стекло прицела).
  - Все четыре юниформа (`state_key`, `grow`, `rim_power`, `cool`) сохраняют смысл — паритет юниформов с x-ray-вариантом сохранён.
- `VTKESP.gd`
  - `set_xray()` (добавлен в 1.9.3) и `p_xray` удаляются; краш из 1.9.3 (Invalid call) уже починен, а глобальный путь теперь мёртвый код.
  - Смысл `p_trig` сужается до «кольцо вспыхивает по окнам» (ON/OFF тумблера): `_trig_event` больше не гейтится им — теги ставятся всегда; `_label_text` показывает суффикс по факту живого окна.
  - `_draw()` передаёт trig-опты только при включённых вспышках: активное окно добавляет `cool` (как есть) и вокруг `refresh()` зовёт `set_entry_xray(id, true/false)`; при выключенных вспышках ринг на окно не реагирует.
- `ThermalVTK.gd`
  - `_mcm_apply` больше не зовёт `_esp.set_xray(...)`; `p_trig` (вспышки по окнам) по-прежнему берётся из `outline_xray`.
  - Тултип `outline_xray` переписывается под семантику событий: вспышка ринга сквозь стену только на время события, теги/надписи живут независимо.

### Отсечение стекла прицела (вариант A — детали)

- Правило: сцена глубже порога `EXCLUDE_METERS ≈ 0.25` — обычная геометрия; ближе порога — «прикреплённая к камере» (линза прицела) — в окклюзию не засчитывается.
- Видимость фрагмента: view-глубина фрагмента с полигон-оффсетным bias сравнивается со сценой (reversed-Z, Forward+); bias съедает разницу роста «обёртки» на силуэте.
- Стоимость: один сэмпл глубины на фрагмент полосы ринга — а полоса тонкая (только кант). Ноль работы на CPU, без рейкастов.
- Согласованный компромисс: предмет, вдавленный вплотную к камере, перестанет прятать ринг на своих пикселях.

## Тесты

- `test_outline` убирает `t_xray_swap` (глобального свапа больше нет), добавляет `t_entry_xray`: `apply()` → материал окклюдед; `set_entry_xray(id, true)` → шейдер материала = x-ray; `(id, false)` → снова окклюдед; второй вызов с тем же значением — no-op.
- `test_shaders` держит парный контракт `Sh.ring(true/false)`; окклюдед-шейдер сохраняет тот же набор юниформов (проверяется существующим тестом на паритет).
- `test_profile`: FakeESP убирает `set_xray`/`xray_calls`; применение конфига больше не должно звать глобальный свап (регресс-гейт).
- `test_esp` убирает `t_set_xray` (регрессия 1.9.3 стала неактуальной), остальное остаётся; лёгкое утверждение: `_label_text` добавляет суффикс только при живом окне (ограничение прежнего пути).
- Ручная проверка в игре: OFF + прицел показывает ринг; OFF за стеной прячет; ON в покое без x-ray; выстрел на 60–100 м зажигает ринг сквозь стену с отсчётом в надписи; прицел + событие = видно.
