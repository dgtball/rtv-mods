# ThermalVTK — обводка в прицеле при PIP off: орбитный детект + выпил авто-PIP

**Дата:** 2026-10-20
**Статус:** утверждено
**Предыдущая спека:** `2026-10-19-thermalvtk-mode-a-palette-outline-design.md` (режим A, палитра, детект стейтов)
**Версия:** 1.5.0 (мажор не нужен: поведение в обычной игре не меняется)

## Проблема

Обводка contour ESP исчезает сквозь увеличенную оптику, когда PIP выключен (нативный
режим: `WeaponRig.ADS()` при `gameData.PIP == false` задаёт `aimFOV = 15.0`, мир рисует
основная камера, SubViewport линзы не используется). В PIP on и без прицела всё работает.

Скопированная цитата пользователя: в режиме FULL (F6) «видно и термомир, и залитую
модельку NPC», а в режиме Contour «видно только термомир». Этот хинт — ключевой
объяснитель (см. «Почему FULL работает») и причина, по которой диагноз считается
закрытым.

### Диагноз (F7-зонд, debug.log 2026-10-19 23:41:06–10, PIP off, прицел на боте)

Кольцо эмитит **один** ключ стейта, но на экране каждого стейта видно **три цвета**,
и это повороты канала R→G→B от калиброванного ключа `DET_ST_*`:

| стейт | `DET_ST_*` (`VTKNVG.gd:76-80`) | наблюдаемые бакеты (avg, n) | ошибка до поворота |
|---|---|---|---|
| normal | (1.00, 0.21, 0.16) | (1,.28,.21) / (.21,1,.28) / (.28,.21,1), n=75–82 | 0.05–0.09 |
| alerted | (1.00, 0.97, 0.46) | (1,1,.59) / (1,.59,1) / (.59,1,1), n=98–104 | 0.13–0.14 |
| hunting | (1.00, 0.34, 1.00) | (1,1,.34) / (1,.34,1) / (.34,1,1), n=86–92 | 0.001–0.005 |
| combat | (0.82, 1.00, 1.00) | (1,1,.78) / (.79,1,1) / (1,.78,1), n=96–105 | 0.03–0.04 |
| nomad | (0.77, 1.00, 0.53) | (0.775,1,.54) + тёмные хвосты, n=74–85 | 0.011 |

Попутно: `Chromatic.gdshader` (поканальный сдвиг R/B) как источник — **отклонён**
аргументированно: он не может дать копию с доминирующим зелёным, а такая копия в
данных есть (normal → (0.211, 1.0, 0.279)). Точный оптический виновник не найден:
`Camera.gd` / `Optic.gdc` не детокенизированы. **Это не блокер** — фикс завязан на
измеренные значения пикселей, а не на причину.

### Почему FULL работает, а Contour — нет

Одна и та же NVG-оверлейная логика (`VTKNVG.gdshader`, ветка `thermalMode`, ближайший
ключ в пределах `0.22`) обслуживает и тепло ботов, и стейты кольца. Разница — в самих
ключах:

| группа ключей | значения | поведение под поворотом канала |
|---|---|---|
| тепло ботов (FULL): `DET_WARM/MID/COLD` | (0.94,0.69,0.94) / (0.94,0.94,0.88) / (0.88,0.94,0.94) — **почти нейтральные** | все 6 повёрнутых копий попадают в `0.22` до какого-нибудь своего ключа → **моделька видна всегда** (тон может сдвинуться) |
| стейты кольца (Contour): `DET_ST_*` | **хроматические**, разнесены на 0.24–1.17 | из 10 повёрнутых копий **5 не опознаются** (d>0.22 → палитра → невидимо), **5 уходят на чужой ключ** (combat → `WARM` = розовая клякса; alerted ↔ hunting) → виден только `rot0` |

Итог: обводка рваная и перекрашенная. Ни калибровка одним цветом, ни подбор порога это
не чинят — повёрнутые копии стейтов лежат дальше, чем между самими стейтами.

## Решение

Сделать детект инвариантным к повороту канала. Ключ сводится к «орбите» из трёх
поворотов (`k.rgb`, `k.brg`, `k.gbr` — только циклические, **не** отражение `k.grb`);
дистанция до ключа = минимум по орбите; «ближайший
побеждает» сохраняется. Проверено на реальных бакетах: **16 из 20 ярких пикселей**
опознаются верно (normal/hunting/combat d=0.0–0.09, alerted 0.13); 4 промаха — только
тёмные пиксели, которые и сейчас не красятся (ложных цветов не появляется).

Орбитное сравнение включается **только** когда поворот реально возможен:
`scopeRotate = isScoped && !gameData.PIP`. Вне этого случая код идентичен текущему —
ноль риска регрессии в обычной игре и в PIP on.

## Изменения по файлам

### `mods/ThermalVTK/VTKNVG.gdshader` (LF)

- Добавить uniform `bool scopeRotate = false`.
- Добавить хелпер (над `fragment()`, рядом с `Goggles`/`ThermalPalette`):

```glsl
float orbitDist(vec3 c, vec3 k)
{
    if (!scopeRotate) {
        return distance(c, k);
    }
    float d = distance(c, k);
    d = min(d, distance(c, k.brg));
    d = min(d, distance(c, k.gbr));
    return d;
}
```

Порядок/набор свиззлов сверены на бакетах зонда: орбита `{rgb, brg, gbr}` даёт ошибку
0.086 / 0.133 / 0.000 / 0.040 / 0.011 (normal/alerted/hunting/combat/nomad), тогда как
неверная `{rgb, grb, brg}` промахивается до 1.106. Тест в `test_shaders.gd` ловит
именно эти два токена свиззла, а не любую вторую `distance`.

- В ветке `thermalMode` заменить все `distance(pixelColor.rgb, X)` на
  `orbitDist(pixelColor.rgb, X)`: `warmKey`, `midKey`, `coldKey`, `mineKey`,
  `markerKey` и пять `st*Key`. Итоговые имена `dWarm`/`dMid`/…/`dStNomad`,
  свёртка `minD`, сравнения `minD == dX` и порог `minD < 0.22` **не меняются** —
  меняется только источник значения.
- Гвард маркера `if (!markNomads || dMark > 0.15) dMark = 10.0;` остаётся как есть
  (считается уже от орбитной дистанции).
- В `else`-ветке (thermalMode off) заменить единственную
  `distance(pixelColor.rgb, mineKey) < 0.15` на `orbitDist(...) < 0.15`.

### `mods/ThermalVTK/VTKNVG.gd` (LF)

- `_apply_uniforms()` (`:307`) выставляет `scopeRotate` одним `set_shader_parameter`.
- `thermalMode = set_thermal and _nvg_active()` (`:321`) **не трогаем**: орбита
  лечит и ключи стейтов, и тепло ботов, без привязки к `bot_paint`.
- `_process()` (`:359`) — дешёвый отслеживание состояния: читать `isScoped` и `PIP` из
  уже загруженного `_game_data` через `VTKData.prop(_game_data, "isScoped", false)` /
  `("PIP", false)`, кэшировать предыдущее значение; при изменении — выставить uniform.
  `_apply_uniforms()` покадрово **не** зовётся, поэтому кэш обязателен; дефолт
  uniform — `false` (до первого кадра поведение прежнее).
- Читать **одной** нодой: `Object.get()` принимает ровно один аргумент, поэтому
  `get(name, default)` здесь использовать нельзя — либо `VTKData.prop`, либо
  `get(name)` + явный фолбэк. Берём `VTKData.prop`.

## Риски (проверяются только в игре)

1. **Ложняк на зелени.** Орбита `normal` включает (0.16, 1.0, 0.21). Ночью измеренные
   бакеты мира тёмные (0.03–0.10) — далеко; риск на яркой зелени днём. Лечится
   поджатием порога с 0.22, если всплывёт.
2. **Ретикл.** Точка/перекрестье красный (`Reticle.gdshader`,
   `reticleColor * vec3(intensity, 0, 0)`) может сесть на орбиту `normal`. Наблюдать;
   если перекрасится — исключить отдельно.
3. **hunting ↔ alerted.** Минимум между их орбитами — 0.124. Реальный пиксель садится
   на своём ключе (0.13 vs 0.25), поэтому «ближайший» выбирает верно; обмен возможен
   только в пограничных кадрах, тон-минутный.
4. **Тёмные пиксели** (4 из 20 в бакетах) остаются нераспознанными — обводка может
   чуть мельчить на краях. Это уже текущее поведение, не регрессия.
